# head-context 제품 그래프

head-context 플러그인 전체를 하나의 지도로 만든 것입니다. AI가 이 플러그인을 고치거나 설명할 때, 파일을 하나씩 뒤지지 않고 이 지도에서 필요한 곳을 먼저 찾게 합니다.

## 왜 그래프를 쓰나

AI에게 "이 기능 고쳐 줘"라고 하면, AI는 보통 파일을 하나씩 열어 가며 관련 코드를 찾습니다. 이 방식에는 문제가 셋 있습니다.

- 찾는 동안 열어 본 파일이 대화를 채웁니다. 정작 필요한 내용이 그 사이에 묻힙니다.
- 코드만 보고는 지금 동작이 일부러 그렇게 만든 것인지, 실수인지 알 수 없습니다.
- 한 곳을 고치면 어디가 같이 바뀌는지 놓치기 쉽습니다.

그래프는 이것들을 미리 이어 둡니다.

- 유저가 하는 일(예: 기록 남기기) → 그때 유저가 받는 글 → 그 글을 내는 기능 → 그 기능의 코드(파일과 줄)
- 정해 둔 규칙 → 그 규칙을 지키는 기능과 코드

AI는 그래프에서 필요한 곳을 먼저 찾고, 그 파일과 줄만 엽니다. 대화에는 지금 판단에 필요한 것만 들어갑니다. "이건 정해 둔 규칙인가"도 그래프에서 확인합니다.

## 이 폴더에 있는 것

| 파일 | 무엇 |
|---|---|
| `USER.md` | 내 AI에 이 그래프를 넣는 법 |
| `LLM.md` | AI가 읽는 조회 안내 |
| `head-context-0.9.17.sqlite` | 그래프 (노드 882, 연결 2,392) |
| `hc_graph.py` | 조회 스크립트 (Python 3 표준 라이브러리만, 읽기 전용) |

## 어떻게 만들었나

0.9.15 그래프를 만든 묶음([`../build/head-context/`](../build/head-context/))을 「새 판을 낼 때의 차례」대로 다시 돌렸습니다. 0.9.16(짧은 말도 사람이 마지막으로 한 말)과 0.9.17(연결 안 된 대화의 첫 말에 작업 세션 제안, 서버 안내문 '읽기' 절, Claude 프로그램 실행의 연결 안 됨 안내 없음, 컴팩트 뒤 먼저 할 것)을 넣었습니다.

- **코드**: head-agent-core commit `d2be2ca`(head-context 0.9.17)에서 스크립트로 처음부터 다시 뽑았습니다. 같은 commit이면 몇 번을 만들어도 결과가 같습니다(sqlite sha256 `697017cd…`, 두 번 같음). 뽑는 규칙은 0.9.15와 같습니다. 새 코드 `core/recovery.mjs#compactRecovery`와 그것을 부르는 `sessions.compactRecovery`가 Claude·Codex 시작 훅(session)에 이어졌습니다.
- **유저가 받는 글**: 플러그인을 임시 폴더에 설치하고 tool과 hook을 돌려 받은 출력 255건에서 가져왔습니다. 0.9.15 때와 같은 232건 뒤에 0.9.16·0.9.17 변경을 보는 23건(R233~R255)을 더했습니다: 작업 브랜치·연결 안 됨·Codex의 컴팩트 뒤 복원, Codex 하위 에이전트의 압축 뒤(복원 없음), Claude 프로그램 실행(sdk-cli)의 연결 안 됨·초기설정 전(입력에 env를 남김), Antigravity 사람 대화의 짧은 말('응')이 presence said로 남는 것(측정), 그리고 검수 뒤 더한 작업 세션 머리 자르기(R247~R255: Claude는 시작·압축 뒤 모두, Codex는 압축 뒤에만 context.md를 잘라 복원 블록 자리를 냄). 앞 232건 중 210건이 글자까지 같습니다. 다른 22건은 모두 서버 안내문 글(첫 줄, 작업 세션의 뜻과 언제, 작업 브랜치의 언제, 새 '읽기' 절 — 서버 안내문을 싣는 Claude·Codex·OpenCode·Antigravity 출력)과 R53 Claude 압축 뒤 시작에 붙은 「컴팩트 뒤 먼저 할 것」입니다.
- **유저가 받는 글의 설명과 규칙**: 화면(출력 종류)이 하나 늘어 35입니다(STA-07 컴팩트 뒤 먼저 할 것). 서버 안내문(SRV-01)에 '읽기', 일 시작 절차(SRV-03)에 '연결되지 않은 대화의 첫 말'이 더해져 화면요소가 120입니다. 규칙이 다섯 늘어 74입니다(pol.first-word-session, pol.read-first, pol.program-quiet-unconnected, pol.compact-recovery, pol.said-any-length). pol.ask-before-load와 pol.first-run-guide의 글을 고쳤습니다.
- **유저가 하는 일**: 0.9.5 때 써 본 기록에 0.9.17 분기(첫 말의 작업 세션 제안, 압축 뒤 복원)를 글로 더했습니다. 0.9.17 글로 다시 써 보지는 않았습니다.
- **검수**: 독립 검수 반영, 재확인 통과(4cb29ec, 남은 지적 없음). 검수 1회(중간 2건, 낮음 5건, 정보 2건)를 반영했습니다.
  - 컴팩트 복원 화면(STA-07)이 작업 맥락 줄이기 규칙 대신 작업 세션 머리 자르기 규칙(pol.session-part-fits)을 가리키게 하고, 그 규칙을 0.9.17(Codex 압축 뒤 자르기, 복원 블록 자리)에 맞췄습니다. 자르기 실행을 더했습니다.
  - 짧은 말 규칙(pol.said-any-length)에 said를 쓰는 Antigravity 훅 둘을 이었고, 대화 목록 화면의 근거가 목록 출력이 아니라 presence 측정값임을 적었습니다.
  - 번호를 민 뒤 남은 낡은 범위, 0.9.17 흐름(첫 말 제안을 받지 않는 분기, 압축 뒤 확인), 겹치던 두 규칙의 역할(제안의 꼴 / 받아야 불러오거나 만듦), 기능 한 줄 둘과 화면요소 글을 고쳤습니다.
  - 커버리지 실행이 압축을 돌리지 않는 것(정보)은 그대로 두었습니다.

같은 방법으로 내 앱의 그래프를 만들려면 [`../build/`](../build/)를 봅니다. 그래프에 무엇을 담는지(정의)와 어떤 차례로 만드는지(순서)가 있습니다. 이 그래프를 만든 스크립트·문서·실행 기록은 [`../build/head-context/`](../build/head-context/)에 있고, 플러그인 새 판을 낼 때 그곳의 차례로 다시 만듭니다.

## 알아 둘 것

- 0.9.17 기준입니다. 그 뒤에 바뀐 코드는 들어 있지 않습니다.
- Codex·OpenCode·Antigravity 쪽은 실제 앱으로 써 보지 않았습니다. Codex·Antigravity 쪽 출력은 앱 없이 훅과 도구 서버를 직접 돌려 받았고, OpenCode 쪽은 플러그인의 훅 함수를 직접 불러 받았습니다. Antigravity 깨우기의 `started`는 실제 agy 프로세스가 있어야 나와서 실행 기록에 없습니다.
- 유저가 하는 일(처음 쓰는 사람 시험)은 0.9.5에서 한 것입니다.
- 그래프는 찾아가는 지도입니다. 최종 답은 그래프가 가리킨 코드와 글을 읽고 냅니다.
