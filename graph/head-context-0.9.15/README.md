# head-context 제품 그래프

head-context 플러그인 전체를 하나의 지도로 만든 것입니다. AI가 이 플러그인을 고치거나 설명할 때, 파일을 하나씩 뒤지지 않고 이 지도에서 필요한 곳을 먼저 찾게 합니다.

## 왜 그래프를 쓰나

AI에게 "이 기능 고쳐 줘"라고 하면, AI는 보통 파일을 하나씩 열어 가며 관련 코드를 찾습니다. 이 방식에는 문제가 셋 있습니다.

- 찾는 동안 열어 본 파일이 대화를 채웁니다. 정작 필요한 내용이 그 사이에 묻힙니다.
- 코드만 보고는 지금 동작이 일부러 그렇게 만든 것인지, 실수인지 알 수 없습니다.
- 한 곳을 고치면 어디가 같이 바뀌는지 놓치기 쉽습니다.

그래프는 이것들을 미리 이어 둡니다.

- 유저가 하는 일(예: 기록 남기기) → 그때 유저가 받는 글 → 그 글을 내는 기능 → 그 기능의 코드(파일과 줄)
- 정해 둔 규칙 → 그 규칙을 지키는 기능과 코드

AI는 그래프에서 필요한 곳을 먼저 찾고, 그 파일과 줄만 엽니다. 대화에는 지금 판단에 필요한 것만 들어갑니다. "이건 정해 둔 규칙인가"도 그래프에서 확인합니다.

## 이 폴더에 있는 것

| 파일 | 무엇 |
|---|---|
| `USER.md` | 내 AI에 이 그래프를 넣는 법 |
| `LLM.md` | AI가 읽는 조회 안내 |
| `head-context-0.9.15.sqlite` | 그래프 (노드 869, 연결 2,337) |
| `hc_graph.py` | 조회 스크립트 (Python 3 표준 라이브러리만, 읽기 전용) |

## 어떻게 만들었나

0.9.10 그래프를 만든 묶음([`../build/head-context/`](../build/head-context/))을 「새 판을 낼 때의 차례」대로 다시 돌렸습니다. 0.9.11~0.9.15에서 더해진 Antigravity 포장과 0.9.15 정리는 그래프 패치(작업 기록 `2026-11-23-군더더기-정리/그래프-패치.md`)를 재료로 넣었습니다.

- **코드**: head-agent-core commit `3b3511f`(head-context 0.9.15)에서 스크립트로 처음부터 다시 뽑았습니다. 같은 commit이면 몇 번을 만들어도 결과가 같습니다(sqlite sha256 `c541f435…`, 두 번 같음). 뽑는 규칙에 Antigravity를 더했습니다.
  - 패키지 루트 `hooks.json`의 두 훅(SessionStart·PreInvocation)과 Antigravity 도구 서버의 앱 도구 `tool:send@antigravity`를 기능으로 뽑습니다.
  - 세 도구 서버가 서로의 peer를 받는 주입 연결과 Antigravity 입구 둘을 넣었습니다.
  - Antigravity가 읽는 agy 쪽 파일 세 칸(대화 기록, ACP 로그, 대화 폴더 메시지)과 language server 외부 연결을 더했습니다.
  - 글이 같아 잘못 맞은 실행 연결 둘을 이름으로 뺐습니다.
- **유저가 받는 글**: 플러그인을 임시 폴더에 설치하고 tool과 hook을 돌려 받은 출력 232건에서 가져왔습니다. 0.9.10 때와 같은 158건 뒤에 Antigravity 74건을 더했습니다. 시작·시작 파일·편지함·압축·도구 서버·보내기·옛 Node·serverInfo 판, 서브에이전트 판정·정리·오판정 막기, 그리고 검수 뒤 더한 등록 안 된 대화의 도구 10개와 편지함 폴더를 읽을 수 없는 경우(Antigravity·Codex)입니다. 앞 158건은 153건이 글자까지 같습니다. 다른 5건은 conversations 도구 설명 한 문장(0.9.15), Codex send 설명(0.9.11), 실행 날짜입니다.
- **유저가 받는 글의 설명과 규칙**: 0.9.10 설명에 Antigravity가 내는 것을 더했습니다. 화면(출력 종류)은 그대로 34이고 화면요소가 다섯, 규칙이 열다섯 늘었습니다.
- **유저가 하는 일**: 0.9.5 때 처음 쓰는 사람처럼 써 본 기록에 Antigravity 분기를 더했습니다. Antigravity로 처음부터 써 본 시험은 하지 않았습니다.
- **검수**: 독립 검수 1회, 지적 8건 반영.
  - 두 Antigravity 훅이 실제로 지나지 않는 줄을 코드 범위에서 뺐습니다. 예를 들어 시작 훅은 압축 뒤 복원 줄을, 매 단계 훅은 시작 파일 줄을 지나지 않습니다.
  - 글이 같아 잘못 붙은 실행 연결(Claude 중계 → 도구 오류)을 뺐습니다.
  - Antigravity send를 부르는 화면요소 셋을 이었습니다. 프로젝트 미등록 오류가 도구 10개 모두에 붙도록 실행을 더했습니다.
  - 편지함 읽기 실패의 앱별 처리 정책이 화면 조회에 닿게 했습니다. 그 정책을 보여 주는 실행도 더했습니다.
  - 데이터 칸에 공유 파일 세 규격 설명을 넣었습니다.
  - 정책 글 둘을 바로잡았습니다.
  - 그 뒤 다시 대조받지는 않았습니다.

같은 방법으로 내 앱의 그래프를 만들려면 [`../build/`](../build/)를 봅니다. 그래프에 무엇을 담는지(정의)와 어떤 차례로 만드는지(순서)가 있습니다. 이 그래프를 만든 스크립트·문서·실행 기록은 [`../build/head-context/`](../build/head-context/)에 있고, 플러그인 새 판을 낼 때 그곳의 차례로 다시 만듭니다.

## 알아 둘 것

- 0.9.15 기준입니다. 그 뒤에 바뀐 코드는 들어 있지 않습니다.
- Codex·OpenCode·Antigravity 쪽은 실제 앱으로 써 보지 않았습니다. Codex·Antigravity 쪽 출력은 앱 없이 훅과 도구 서버를 직접 돌려 받았고, OpenCode 쪽은 플러그인의 훅 함수를 직접 불러 받았습니다. Antigravity 깨우기의 `started`는 실제 agy 프로세스가 있어야 나와서 실행 기록에 없습니다.
- 유저가 하는 일(처음 쓰는 사람 시험)은 0.9.5에서 한 것입니다.
- 그래프는 찾아가는 지도입니다. 최종 답은 그래프가 가리킨 코드와 글을 읽고 냅니다.
