# head-context 제품 그래프

head-context 플러그인 전체를 하나의 지도로 만든 것입니다. AI가 이 플러그인을 고치거나 설명할 때, 파일을 하나씩 뒤지지 않고 이 지도에서 필요한 곳을 먼저 찾게 합니다.

## 왜 그래프를 쓰나

AI에게 "이 기능 고쳐 줘"라고 하면, AI는 보통 파일을 하나씩 열어 가며 관련 코드를 찾습니다. 이 방식에는 문제가 셋 있습니다.

- 찾는 동안 열어 본 파일이 대화를 채웁니다. 정작 필요한 내용이 그 사이에 묻힙니다.
- 코드만 보고는 지금 동작이 일부러 그렇게 만든 것인지, 실수인지 알 수 없습니다.
- 한 곳을 고치면 어디가 같이 바뀌는지 놓치기 쉽습니다.

그래프는 이것들을 미리 이어 둡니다.

- 유저가 하는 일(예: 기록 남기기) → 그때 유저가 받는 글 → 그 글을 내는 기능 → 그 기능의 코드(파일과 줄)
- 정해 둔 규칙 → 그 규칙을 지키는 기능과 코드

AI는 그래프에서 필요한 곳을 먼저 찾고, 그 파일과 줄만 엽니다. 대화에는 지금 판단에 필요한 것만 들어갑니다. "이건 정해 둔 규칙인가"도 그래프에서 확인합니다.

## 이 폴더에 있는 것

| 파일 | 무엇 |
|---|---|
| `USER.md` | 내 AI에 이 그래프를 넣는 법 |
| `LLM.md` | AI가 읽는 조회 안내 |
| `head-context-0.9.5.sqlite` | 그래프 (노드 744, 연결 1,857) |
| `hc_graph.py` | 조회 스크립트 (Python 3 표준 라이브러리만, 읽기 전용) |

## 어떻게 만들었나

- **코드**: head-agent-core commit `04e9328`(head-context 0.9.5)에서 스크립트로 뽑았습니다. 같은 commit이면 몇 번을 만들어도 결과가 같습니다.
- **유저가 받는 글**: 플러그인을 실제로 설치하고 tool과 hook을 돌려 받은 출력 112건에서 가져왔습니다. 글과 기능의 연결도 이 실행 기록에서 기계적으로 이었습니다.
- **유저가 하는 일**: 처음 쓰는 사람처럼 Claude Code로 11가지 일을 실제로 해 본 기록으로 썼습니다.
- **검수**: 만들지 않은 AI가 그래프를 코드와 실제 출력에 두 번 대조했고, 나온 지적을 고쳤습니다.

같은 방법으로 내 앱의 그래프를 만들려면 [`../build/`](../build/)를 봅니다. 그래프에 무엇을 담는지(정의)와 어떤 차례로 만드는지(순서)가 있습니다.

## 알아 둘 것

- 0.9.5 기준입니다. 그 뒤에 바뀐 코드는 들어 있지 않습니다.
- Codex와 OpenCode 쪽은 실제로 써 보지 않고 코드만 보고 썼습니다.
- 그래프는 찾아가는 지도입니다. 최종 답은 그래프가 가리킨 코드와 글을 읽고 냅니다.
