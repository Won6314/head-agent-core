# head-context 제품 그래프

head-context 플러그인 전체를 하나의 지도로 만든 것입니다. AI가 이 플러그인을 고치거나 설명할 때, 파일을 하나씩 뒤지지 않고 이 지도에서 필요한 곳을 먼저 찾게 합니다.

## 왜 그래프를 쓰나

AI에게 "이 기능 고쳐 줘"라고 하면, AI는 보통 파일을 하나씩 열어 가며 관련 코드를 찾습니다. 이 방식에는 문제가 셋 있습니다.

- 찾는 동안 열어 본 파일이 대화를 채웁니다. 정작 필요한 내용이 그 사이에 묻힙니다.
- 코드만 보고는 지금 동작이 일부러 그렇게 만든 것인지, 실수인지 알 수 없습니다.
- 한 곳을 고치면 어디가 같이 바뀌는지 놓치기 쉽습니다.

그래프는 이것들을 미리 이어 둡니다.

- 유저가 하는 일(예: 기록 남기기) → 그때 유저가 받는 글 → 그 글을 내는 기능 → 그 기능의 코드(파일과 줄)
- 정해 둔 규칙 → 그 규칙을 지키는 기능과 코드

AI는 그래프에서 필요한 곳을 먼저 찾고, 그 파일과 줄만 엽니다. 대화에는 지금 판단에 필요한 것만 들어갑니다. "이건 정해 둔 규칙인가"도 그래프에서 확인합니다.

## 이 폴더에 있는 것

| 파일 | 무엇 |
|---|---|
| `USER.md` | 내 AI에 이 그래프를 넣는 법 |
| `LLM.md` | AI가 읽는 조회 안내 |
| `head-context-0.9.18.sqlite` | 그래프 (노드 925, 연결 2,491) |
| `hc_graph.py` | 조회 스크립트 (Python 3 표준 라이브러리만, 읽기 전용) |

## 어떻게 만들었나

0.9.17 그래프를 만든 묶음([`../build/head-context/`](../build/head-context/))을 「새 판을 낼 때의 차례」대로 다시 돌렸습니다. 0.9.18(터미널 Antigravity 대화도 깨우기: 프로세스마다 한 번 깨우기 등록, 등록 명령 자동 승인, 깨우기 판정 차례, 깨우기 열쇠 기록)을 넣었습니다.

- **코드**: head-agent-core commit `043ffdb`(head-context 0.9.18)에서 스크립트로 처음부터 다시 뽑았습니다. 같은 commit이면 몇 번을 만들어도 결과가 같습니다(sqlite sha256 `714efa01…`, 두 번 같음). 뽑는 규칙에 셋을 더했습니다.
  - 루트 `hooks.json`의 도구 전 훅(PreToolUse, matcher `run_command`)을 기능 `hook:antigravity:PreToolUse`로 뽑고, 처리 코드는 `hosts/antigravity/pretool.mjs#decide`입니다.
  - 인자 없는 등록 명령은 `process.argv`를 읽지 않아 명령줄 규칙에 걸리지 않으므로, 이름 표(`MANUAL_CLI`)로 `cli:antigravity-wake-register`를 넣었습니다.
  - 명령 글을 만들기만 하는 `wake-command.mjs#registerCommand`가 `.mjs` 경로 글 때문에 "경로로 실행"으로 잡힌 연결 하나를 이름으로 뺐습니다(`PATH_TEXT_NOT_RUN`). 깨우기 신호는 `wake.mjs`의 `acpSignal`·`terminalSignal` 두 자리로 잇습니다.
- **유저가 받는 글**: 플러그인을 임시 폴더에 설치하고 tool과 hook을 돌려 받은 출력 299건에서 가져왔습니다. 0.9.17 때와 같은 255건 뒤에 0.9.18을 보는 44건(R256~R299)을 더했습니다. 실제 agy는 띄우지 않고, 이름이 `agy`인 가짜 node 프로세스가 대화를 쥔 agy 노릇을 합니다(잠금 파일을 열어 두고, 열쇠를 검사하는 SendAgentMessage를 흉내 내고, 훅·등록 명령을 자기 자식으로 돌림). 본 것: 첫 모델 호출의 등록 지시, 두 번째 호출·`/clear` 뒤 새 대화에는 없음, 등록 명령 성공과 실패 넷, 도구 전 훅의 자동 승인·허락(진입 스크립트가 없을 때의 셸 대체 포함), 세 앱의 보내기가 started(열쇠 헤더 일치, 신호 본문에 보낸 글 없음)와 깨어난 턴의 원문 주입, 화면에서 떠난 대화와 꺼진 agy는 queued, 다시 띄우면 다시 요청하고 옛 기록을 지움, 이미 요청받은 프로세스의 뒤 호출에서는 정리가 돌지 않고 새 프로세스가 처음 요청받을 때만 돎(R295~R299, 043ffdb), ACP·print·`--remote-agent`·서브에이전트·agy 없음에는 요청 없음, 옛 Node도 요청. 앞 255건 중 238건이 글자까지 같습니다. 다른 17건은 모두 보내기 설명 글(Codex·Antigravity 도구 목록 R71·R171)과 Antigravity 서버 안내문의 보내기 줄(그 줄을 싣는 Antigravity 시작 훅·도구 서버 출력 15건)입니다.
- **유저가 받는 글의 설명과 규칙**: 화면(출력 종류)이 둘 늘어 37입니다(MSG-03 깨우기 등록 지시, CLI-02 깨우기 등록 명령 출력). 화면요소는 126입니다. 도구 전 훅의 결정은 agy가 읽는 기계용 답이라 화면을 두지 않았습니다. 규칙이 넷 늘어 78입니다(pol.agy-wake-register-ask, pol.agy-wake-register-approve, pol.agy-wake-key-record, pol.agy-wake-key-prune). pol.agy-wake-owner를 판정 차례로 고쳐 쓰고, pol.agy-owner-pid와 pol.hook-failure-says(도구 전 훅은 실패 줄 대신 허락)를 고쳤습니다. 데이터 칸 「Antigravity 깨우기 열쇠 기록」이 생겼습니다.
- **유저가 하는 일**: 다른 대화에 말 전하기(`ua.message`)에 받는 쪽이 터미널 agy인 분기(프로세스마다 한 번 등록)를 글로 더했습니다. 0.9.18 실제 확인(실제 터미널 agy, Linux)이 근거이고, 이 문서 묶음으로 다시 써 보지는 않았습니다.
- **검수**: 독립 검수 반영, 재확인 대기. 검수 1회(중간 2건, 낮음 4건)를 반영했습니다.
  - 등록 명령도 presence와 같은 방법으로 agy를 찾아야 한다는 규칙(pol.agy-owner-pid)을 등록 명령 기능에 이었습니다.
  - 도구 전 훅이 10초를 넘기면 agy가 그 셸 명령을 거절한다는 사실을 도구 전 훅 기능 한 줄과 자동 승인 규칙에 적어 그 기능에서 보이게 했습니다. 근거는 셸 대체 전 판에서 잰 것이고, 셸 대체 뒤에는 다시 재지 않았다고 적었습니다.
  - 훅 실패 화면 상태 줄의 시간 초과 예외, 프로세스 표 칸의 일반 뜻, LLM.md의 started 줄, 근거 번호 둘을 고쳤습니다. 진입 스크립트가 없을 때의 실행(R272)은 이제 설치본 hooks.json의 명령 글을 읽어 돌립니다.

같은 방법으로 내 앱의 그래프를 만들려면 [`../build/`](../build/)를 봅니다. 그래프에 무엇을 담는지(정의)와 어떤 차례로 만드는지(순서)가 있습니다. 이 그래프를 만든 스크립트·문서·실행 기록은 [`../build/head-context/`](../build/head-context/)에 있고, 플러그인 새 판을 낼 때 그곳의 차례로 다시 만듭니다.

## 알아 둘 것

- 0.9.18 기준입니다. 그 뒤에 바뀐 코드는 들어 있지 않습니다.
- Codex·OpenCode·Antigravity 쪽은 실제 앱으로 써 보지 않았습니다. Codex·Antigravity 쪽 출력은 앱 없이 훅과 도구 서버를 직접 돌려 받았고, OpenCode 쪽은 플러그인의 훅 함수를 직접 불러 받았습니다. Antigravity 깨우기의 `started`는 ACP 쪽은 실행 기록에 없고, 터미널 쪽은 가짜 agy 프로세스로 본 것입니다(실제 터미널 agy 확인은 0.9.18 실제 확인).
- 유저가 하는 일(처음 쓰는 사람 시험)은 0.9.5에서 한 것입니다.
- 그래프는 찾아가는 지도입니다. 최종 답은 그래프가 가리킨 코드와 글을 읽고 냅니다.
