# head-context 제품 그래프

head-context 플러그인 전체를 하나의 지도로 만든 것입니다. AI가 이 플러그인을 고치거나 설명할 때, 파일을 하나씩 뒤지지 않고 이 지도에서 필요한 곳을 먼저 찾게 합니다.

## 왜 그래프를 쓰나

AI에게 "이 기능 고쳐 줘"라고 하면, AI는 보통 파일을 하나씩 열어 가며 관련 코드를 찾습니다. 이 방식에는 문제가 셋 있습니다.

- 찾는 동안 열어 본 파일이 대화를 채웁니다. 정작 필요한 내용이 그 사이에 묻힙니다.
- 코드만 보고는 지금 동작이 일부러 그렇게 만든 것인지, 실수인지 알 수 없습니다.
- 한 곳을 고치면 어디가 같이 바뀌는지 놓치기 쉽습니다.

그래프는 이것들을 미리 이어 둡니다.

- 유저가 하는 일(예: 기록 남기기) → 그때 유저가 받는 글 → 그 글을 내는 기능 → 그 기능의 코드(파일과 줄)
- 정해 둔 규칙 → 그 규칙을 지키는 기능과 코드

AI는 그래프에서 필요한 곳을 먼저 찾고, 그 파일과 줄만 엽니다. 대화에는 지금 판단에 필요한 것만 들어갑니다. "이건 정해 둔 규칙인가"도 그래프에서 확인합니다.

## 이 폴더에 있는 것

| 파일 | 무엇 |
|---|---|
| `USER.md` | 내 AI에 이 그래프를 넣는 법 |
| `LLM.md` | AI가 읽는 조회 안내 |
| `head-context-0.9.10.sqlite` | 그래프 (노드 784, 연결 1,996) |
| `hc_graph.py` | 조회 스크립트 (Python 3 표준 라이브러리만, 읽기 전용) |

## 어떻게 만들었나

0.9.5 그래프를 만든 방법과 파일을 그대로 쓰고, 0.9.10에서 바뀐 것을 다시 뽑거나 고쳤습니다.

- **코드**: head-agent-core commit `7a5896c`(head-context 0.9.10)에서 스크립트로 처음부터 다시 뽑았습니다. 같은 commit이면 몇 번을 만들어도 결과가 같습니다. 코드에서 정의와 호출을 뽑는 규칙은 0.9.10 코드 모양에 맞춰 세 곳을 고쳤고, 고친 규칙을 0.9.5 코드에 돌려도 뽑힌 결과가 같습니다. 그 위에 기능·화면·데이터를 잇는 규칙은 검수를 거치며 여럿 고쳤습니다. MCP 도구 호출이 모두 지나는 공통 갈래를 도구 기능에 잇기, 출력 글을 코드 자리로 잇는 범위를 화면설계서가 적은 생성자로 좁히기, 글이 같아 잘못 맞은 실행 연결 둘을 이름으로 빼기, 한 파일 안에서 데이터 대상을 줄 단위로 나누기 등입니다. 이 규칙들은 0.9.5 그래프도 바꿉니다. 예를 들어 공통 갈래 규칙을 0.9.5에 넣으면 기능→코드 연결이 43개에서 53개가 됩니다.
- **유저가 받는 글**: 0.9.10 플러그인을 실제로 설치하고 tool과 hook을 돌려 받은 출력 158건에서 가져왔습니다. 0.9.5 때와 같은 112건에, 새로 바뀐 동작(작업 맥락 줄이기, 참조파일, 달 꼴 이름 거절, Codex 대화 정보 다시 쓰기, node:sqlite가 없는 옛 Node)을 보는 27건과, 검수가 짚은 출력(옛 Node에서 도구 10개 모두, save가 거절하는 본문·경로, 잠금 실패, OpenCode 훅 등)을 보는 19건을 더했습니다. 글과 기능의 연결은 이 실행 기록에서 기계적으로 이었습니다.
- **유저가 받는 글의 설명과 규칙**: 0.9.5 때 쓴 설명에서 0.9.10 출력과 코드가 달라진 곳만 고쳤습니다. 0.9.5 대비 화면(출력 종류) 하나와 화면요소 여덟, 규칙 일곱이 늘었습니다.
- **유저가 하는 일**: 0.9.5 때 처음 쓰는 사람처럼 Claude Code로 11가지 일을 실제로 해 본 기록으로 썼습니다. 0.9.10에서는 다시 해 보지 않았고, 그 뒤 판에서 바뀐 것은 해당 줄에 적었습니다.
- **검수**: 0.9.5 판은 만들지 않은 AI가 코드와 실제 출력에 두 번 대조했습니다. 0.9.10 판도 만들지 않은 AI가 두 번 대조했습니다.
  - 첫 검수: 무작위 표본 29개 중 27개가 맞았고 지적이 12건(높음 1, 중간 4, 낮음 7) 나왔습니다. 가장 큰 지적은 MCP 도구 호출이 모두 지나는 공통 갈래가 어느 기능에도 이어지지 않아, 그 갈래의 코드(옛 Node 검사 등)를 바꿀 때 걸리는 도구가 안 보였다는 것입니다.
  - 재검수: 12건 중 10건은 고쳐졌고 2건(데이터 분류, 출력을 내는 기능 빠짐)은 일부만 고쳐졌다고 봤습니다. 새 표본 30개는 모두 맞았습니다. 새 지적은 6건(중간 1, 낮음 5)이었고, 가장 큰 것은 첫 지적을 고친 규칙이 공통 갈래를 너무 넓게 이어 설정 코드 등의 영향 조회에 도구가 부풀려 나온다는 것이었습니다.
  - 새 지적 6건을 모두 고쳤습니다(공통 갈래를 도구마다 실제로 지나는 줄로 좁힘 — 부풀었던 코드 25개·기능 110쌍만 빠지고 다른 영향 조회는 그대로). 그 뒤 다시 대조받지는 않았습니다.

같은 방법으로 내 앱의 그래프를 만들려면 [`../build/`](../build/)를 봅니다. 그래프에 무엇을 담는지(정의)와 어떤 차례로 만드는지(순서)가 있습니다.

## 알아 둘 것

- 0.9.10 기준입니다. 그 뒤에 바뀐 코드는 들어 있지 않습니다.
- Codex와 OpenCode 쪽은 실제 앱으로 써 보지 않았습니다. Codex 쪽 출력은 Codex 앱 없이 훅과 도구 서버를 직접 돌려 받았고, OpenCode 쪽은 플러그인의 훅 함수를 직접 불러 받았습니다.
- 유저가 하는 일(처음 쓰는 사람 시험)은 0.9.5에서 한 것입니다.
- 그래프는 찾아가는 지도입니다. 최종 답은 그래프가 가리킨 코드와 글을 읽고 냅니다.
