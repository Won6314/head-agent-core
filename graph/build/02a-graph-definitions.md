# 제품 그래프 정의

제품 그래프는 유저가 하는 일(유저 활동·화면·화면요소)과 시스템이 하는 일(기능·코드·DB)을 노드와 연결로 기록한 인덱스다. 만드는 순서는 [그래프 실행지침](02b-graph-workflow.md)에 있다.

**정본.** 그래프는 원본에서 파싱해 만든다. 코드에서 나오는 노드의 원본은 코드이고, 나머지의 원본은 문서다. 그래프에 직접 쓰는 것은 정책의 규칙 한 줄, 기능의 한 줄, DB·계측 이벤트의 뜻 한 줄뿐이다.

**ID.** 코드에서 나오는 노드의 ID는 코드에서 기계적으로 뽑는다. 문서에서 나오는 노드의 ID는 문서에 적는다.

## 노드 타입

| 노드 타입 | 정의 | 원본 |
|---|---|---|
| 제품코어 | 제품의 정체성·타겟 유저·제공 가치·브랜딩 | 제품 정의서 |
| 유저저니 | 유저가 제품을 알게 되고, 쓰고, 떠나고, 다시 오는 단계 | 유저 저니맵 |
| IA | 화면 목록과 그 묶음, 전역 메뉴 | IA 문서 |
| 유저 활동 | 유저가 한 가지 일로 받아들이는 활동과 그 차례 | 유저플로우 기획서 |
| 화면 | 페이지 하나의 한 상태 | 화면설계서 |
| 화면요소 | 화면에서 유저가 보거나, 입력하거나, 결과를 받는 것 하나 | 화면설계서의 화면요소 절 |
| 정책 | 조건 / 주체 / 행위로 쓴 규칙 하나 | 그래프 |
| 기능 | 시스템이 요청 하나를 받아 처리하는 단위 | 코드 |
| 코드 | 파일·클래스·함수 등 이름 붙은 코드와 그 묶음 | 코드 |
| 데이터 | 코드가 읽고 쓰는 값 중 DB가 아닌 것 | 코드 |
| 외부 연결 | 코드가 제품 밖의 서비스를 호출하는 곳 | 코드 |
| DB | 테이블과 컬럼 | 코드(스키마) |
| 계측 이벤트 | 코드가 분석 도구로 보내는 이벤트와 파라미터 | 코드 |

## 제품코어

**정의.** 제품이 무엇이고, 누구를 위해, 무엇을 주며, 어떤 모습으로 보이는지 정한 것. 제품 하나에 하나다.

**문서.** 제품 정의서. 정체성, 타겟 유저, 제공 가치, 브랜딩을 담는다.

**연결.** 없다. 모든 정책과 유저 활동이 제품코어와 부딪히지 않는지 본다.

## 유저저니

**정의.** 유저가 제품을 알게 되고, 쓰고, 떠나고, 다시 오기까지의 단계. 제품 하나에 문서 하나다.

**문서.** 유저 저니맵. 누구이고 어떤 상황인가, 단계, 단계마다 원하는 것, 떠나는 곳, 돌아오는 계기를 담는다. 제품 밖의 상황(알게 된 경로, 시간이 지나 다시 찾음)은 여기에 쓴다.

**연결.** 없다. 유저 활동의 '다음 활동'과 저니의 단계 순서가 맞는지 본다.

## IA

**정의.** 화면 목록, 화면 묶음, 모든 화면에서 갈 수 있는 메뉴(헤더·사이드바 등), 유저가 처음 들어오는 화면.

**문서.** IA 문서 하나.

**속성.** 화면마다 `IA 묶음` 하나.

**연결.** 없다. 화면 사이의 이동은 기능의 navigate 코드에서 읽는다.

## 유저 활동

**정의.** 유저가 한 가지 일로 받아들이는 활동. 문제(유저가 조작을 고르기 전에 느끼는 상황)와 목표(유저가 어떤 대상에 하려는 일)가 둘 다 같으면 하나의 유저 활동이다.

**문서.** 활동마다 유저플로우 기획서 하나. 무엇을 하는가, 언제 하게 되나, 차례(시작, 단계, 분기, 끝), 얻는 것, 다음 활동을 담는다. 각 단계는 그 단계가 일어나는 화면요소의 ID를 적는다.

**속성.** ID, 한 줄, 문서 위치

**연결.**
- 유저 활동 → 화면요소: 기획서의 단계에 적힌 화면요소.
- 유저 활동 → 유저 활동: 기획서의 '다음 활동'.

## 화면

**정의.** 페이지 하나의 한 상태. 주된 사용 목적이 다르면 다른 화면이다.
- 같은 주소라도 상태에 따라 목적이 바뀌면 다른 화면이다.
- 모달, 시트, 드롭다운 메뉴는 따로 화면이다.
- 같은 자리에서 펼쳐지는 부분(접힌 글 펼치기 등)은 화면이 아니라 화면요소다.
- 여러 화면에 같이 붙는 영역(헤더, 사이드바, 푸터)은 공통 영역이라는 화면이다.

**ID.** `<묶음 앞머리>-<번호>` (예: `CHT-01`). 상태가 다르면 번호가 다르다.

**문서.** 화면마다 화면설계서 하나.

| 절 | 담는 것 |
|---|---|
| 이 화면이 무엇인가 | 화면 ID와 이름, URL, 상태, 그림 파일, 붙는 공통 영역 |
| 개요 | 유저가 왜 오고, 어디서 오는가 |
| 화면 흐름 | 유저가 보통 무엇을 보고, 무엇을 하고, 어디로 가는가 |
| 화면요소 | 번호마다: 보여 주는 것, 조작하면 일어나는 일, 보이는 조건, 문구 |
| 화면 정책 | 화면이 스스로 하는 일. 조건 / 주체 / 행위 |

**그림.** 화면마다 원본(html, png)과 위치 매칭본(html, png). 위치 매칭본은 화면요소마다 번호 상자를 그린 것이고, 번호는 화면설계서의 화면요소 번호와 같다. 배치와 시각 표현은 그림에만 있다.

**연결.**
- 화면 → 화면요소: 화면설계서의 화면요소 절에 적힌 것.
- 화면 → 화면: 그 화면에 붙는 공통 영역.
- 화면 → 정책: 화면 정책 절에 적힌 정책.
- 화면 → 코드: 그 화면을 그리는 코드. 페이지면 페이지 컴포넌트, 모달·시트·공통 영역이면 그 컴포넌트.
- 화면 → 기능: 그 화면을 그리는 코드에서 call·framework-invoked·callback으로 호출하는 기능(화면이 열릴 때 실행되는 기능).

## 화면요소

**정의.** 화면에서 유저가 하나로 보고 다루는 것. 유저가 보는 것, 입력하는 것, 결과를 받는 것이 모두 화면요소다. 화면요소 안에 화면요소가 있을 수 있다. 코드의 컴포넌트와 1:1이 아니다.

**원본.** 화면설계서의 화면요소 절. 번호 하나가 화면요소 하나이고, 하위 번호(`3-1`)는 안의 화면요소다.

**ID.** `<화면 ID>#<번호>` (예: `CHT-01#5`)

**속성.** ID, 한 줄, 위치

**연결.**
- 화면요소 → 화면요소: 하위 번호.
- 화면요소 → 기능: 그 화면요소를 조작하면 실행되는 기능.
- 기능 → 화면요소: 그 기능의 결과나 가져온 내용을 보여 주는 화면요소.

## 화면이 없는 제품

CLI, 플러그인, 라이브러리처럼 화면이 없는 제품은 이렇게 적용한다.
- 화면: 유저가 받는 출력 한 종류. 명령 출력, tool 결과, hook이 넣는 글, 오류 메시지가 각각 화면이다.
- 화면요소: 그 출력 안의 한 부분.
- 유저: 사람, 또는 사람이 쓰는 AI agent.
- 그림: 화면 그림 대신 실제로 받은 출력 원문을 남긴다.

## 정책

**정의.** 조건 / 주체 / 행위로 쓴 규칙 하나. "이런 상황에서 / 누가 / 무엇을 한다(하지 않는다)." 종류는 둘이다.
- 처리 정책: 기능이 지킨다.
- 표시 정책: 화면이 지킨다(보이는 조건, 배치, 문구).

정책이 아닌 것: 코드끼리 맞추는 약속(같은 id 문자열 등), 기술적 제약. 이것은 코드 주석이나 이벤트의 뜻에 쓴다.

**원본.** 그래프에 규칙 한 줄을 직접 쓴다. 표시 정책은 화면설계서의 화면 정책 절에도 쓴다.

**연결.**
- 정책 → 기능: 그 처리 정책을 코드로 지키는 기능.
- 화면 → 정책: 그 화면이 지키는 표시 정책.

## 기능

**정의.** 시스템이 요청 하나를 받아 처리하는 단위. 아래 하나가 기능 하나다.
- API 엔드포인트 하나
- 서버 액션 하나
- 정해진 시간에 실행되는 작업 하나
- 서버 시작 때 실행되는 함수 하나
- 외부 서비스가 보내오는 요청(웹훅)을 받는 엔드포인트 하나
- API를 호출하지 않는 프론트 이벤트 핸들러 하나(모달 열기, 화면 이동, 펼치기)
- slash command, MCP tool, hook, CLI 명령 하나

같은 API를 호출하는 프론트 요소가 여럿이어도 기능은 하나다. 기획에서 말하는 "기능" 크기(예: 캐릭터와 대화하기)는 기능이 아니라 유저 활동이다.

**원본.** 코드. 스크립트로 뽑는다.

**ID.**

| 종류 | ID |
|---|---|
| API | `<서비스>:<메서드> <경로>` |
| 서버 액션 | `<서비스>:action:<함수 이름>` |
| 정해진 시간 | `<서비스>:cron:<작업 이름>` |
| 서버 시작 | `<서비스>:startup:<파일>.<함수>` |
| 프론트 | `fe/<경로>/<컴포넌트>@<이벤트>:<대상>` |
| slash command·MCP tool·hook·CLI | `<종류>:<이름>` (예: `tool:save`, `hook:SessionStart`) |

- `<서비스>`는 서비스가 하나여도 붙인다(`api`, `web`).
- 프론트 `<이벤트>`는 React 이벤트 이름에서 `on`을 뗀 것(`click`). `<대상>`은 핸들러 이름, 없으면 요소 id, 둘 다 없으면 `요소#순번`. 화면이 열릴 때 스스로 실행되는 것은 `@effect:<이름>`.

**속성.** ID, 종류, 한 줄(무엇을 하는지)

**연결.**
- 기능 → 코드: 그 기능의 요청을 받는 함수. API 핸들러와, 그 API를 호출하는 프론트 이벤트 핸들러.
- 화면요소 → 기능, 기능 → 화면요소, 정책 → 기능, 화면 → 기능: 위 절들.
- 외부 연결 → 기능: 외부 서비스를 거쳐 실행되는 기능(결제사 → 결제 결과 웹훅).

## 코드

**정의.** 제품 코드의 이름 붙은 단위(파일, 모듈, 클래스, 타입, 함수, 메서드, 핸들러)와 그 묶음. 묶음은 C4를 따른다: Component(앱 안의 모듈), Container(따로 실행되는 단위: 브라우저, web 서버, API, 워커, DB), Context(제품과 외부 연결).

**원본.** 코드. 파일마다 구문 트리로 읽어 정의와 참조를 뽑는다. 같은 커밋이면 같은 결과가 나온다. 함수 안의 분기·실행 순서는 저장하지 않고, 필요하면 줄 범위로 원본을 읽는다.

**속성.** 파일, 줄 범위, 종류

**연결.**
- 코드 → 코드 `reference`. 종류는 call, callback, framework-invoked(프레임워크가 대신 호출: 가드, DI, 파일 이름 라우트, 데코레이터), render, type reference, re-render, response, enqueue, navigate(화면 이동: 가는 곳의 페이지 코드), http(다른 서비스의 엔드포인트 호출), defines(함수 안에 정의한 핸들러).
- 묶음 → 코드: 포함.
- 코드 → DB, 데이터: read / write.
- 코드 → 외부 연결: 그 코드가 호출하는 외부 서비스.
- 코드 → 계측 이벤트: 그 코드가 보내는 이벤트.

어느 기능의 처리 코드에서 reference를 따라가도 도달하지 않는 코드는 목록으로 만든다(빠진 기능이거나 죽은 코드).

## 데이터

**정의.** 코드가 읽거나 쓰는 값 중 DB가 아닌 것: 쿠키, 기기 저장, env, 설정 파일, 기능 플래그.

**연결.** 코드 → 데이터: read / write.

## 외부 연결

**정의.** 코드가 제품 밖의 서비스를 호출하는 곳. 주소 호출, SDK 호출, 외부 페이지로 리다이렉트가 모두 해당한다. 실행 중에 정해지는 주소는 고정된 부분까지 적는다(`/api/characters/:id`).

**연결.** 코드 → 외부 연결, 외부 연결 → 기능.

## DB

**정의.** 테이블과 그 컬럼. 외래키로 같은 컬럼을 가리키는 컬럼은 하나로 묶는다. 이름만 같은 컬럼(`id`, `created_at`)은 따로 둔다.

**원본.** 스키마 코드. 테이블, 컬럼과 타입, 외래키를 뽑는다.

**속성.** 테이블·컬럼마다 뜻 한 줄(그래프에 직접 쓴다).

**연결.** 코드 → DB: read / write.

## 계측 이벤트

**정의.** 코드가 분석 도구로 실제로 보내는 이벤트와 그 파라미터. 이름이 같은 파라미터는 하나로 묶는다. 선언만 있고 보내는 코드가 없는 이벤트는 노드로 두지 않고 목록으로 만든다.

**원본.** 코드. 이벤트 이름, 채널, 보내는 코드, 파라미터, 코드에 적힌 값을 뽑는다.

**속성.** 이벤트·파라미터마다 뜻 한 줄(그래프에 직접 쓴다).

**연결.** 코드 → 계측 이벤트.

## 연결 이름

연결 종류 이름은 양쪽 노드 타입을 그대로 적는다(`기능→화면요소`). 예외는 포함, 코드 → 코드의 reference 종류, read / write 셋이다. 새 이름은 사용자 승인을 받고 이 문서에 적은 뒤에 쓴다.

## 정합성 검사

| 그래프에서 보이는 것 | 뜻 |
|---|---|
| 제품코어와 부딪히는 정책 | 정책이나 제품코어 중 하나가 틀렸다 |
| 화면요소 → 기능이 있는데 그 화면요소를 가리키는 유저 활동이 없다 | 기획에 빠진 일이거나 쓰이지 않는 기능 |
