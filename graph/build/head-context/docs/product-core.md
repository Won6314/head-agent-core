# 제품 정의서 — head-context

> 제품코어는 제품 주인이 정한 것(2026-10-31)을 그대로 옮겼다. '할 수 있는 것'과 '지키는 모습'은 0.9.5 코드·실행으로 확인하고 0.9.10에서 바뀐 곳을 고쳤다.
> 대상: head-context 0.9.15 (head-agent-core `e96f5aa`, `packages/context`). 0.9.11~0.9.15의 Antigravity 포장을 더했다.

## 제품코어


**정체성:** LLM 대화(Claude Code·Codex·Antigravity·OpenCode)에 붙어 컨텍스트를 쌓아 주는 플러그인.

**목표: LLM이 일을 잘하게 한다.**

**방법: 컨텍스트를 잘 쌓는다.** 무엇을, 언제, 얼마만큼 넣을지를 제품이 정한다. 기록은 요약과 근거 파일 링크로 쌓이고, 다음 대화는 그 압축된 지도를 먼저 받은 뒤 필요한 곳만 링크를 따라 내려간다(제품 그래프와 같은 방식).

**타겟 유저:** 자기만의 LLM 사용법이 없는 AI 입문~중간 사용자.
- 이 제품을 직접 부르는 쪽은 그 사람의 에이전트(Claude·Codex·Antigravity 대화)다. 사람은 말만 하고, 도구는 에이전트가 부른다.
- 대화 안의 작업(포크·하위 에이전트, Antigravity 서브에이전트, `claude -p`로 띄운 워커)도 에이전트지만 기록은 읽기만 한다.

**큰 동기:** 에이전트와 하는 일은 긴데 컨텍스트는 쉽게 망가진다.
- 호스트의 압축은 믿을 수 없다. 무엇을 남길지 호스트가 정하고, 합의·다음 할 일이 빠지거나 바뀌어도 알 수 없다.
- 파일을 통째로 불러오는 리콜은 컨텍스트를 망친다. 지금 판단에 필요 없는 것이 들어와 필요한 것을 묻는다.

**제공 가치:** 자기 사용법이 없어도, 제품이 일하는 방식과 컨텍스트 쌓는 법을 갖춰 주어 LLM이 일을 잘한다.

## 할 수 있는 것 (수단)

1. **지침** — 에이전트가 일하는 방식을 맞춘다. 동의를 받아 코어 지침을 켜고 시작·/clear·압축 때마다 넣는다. 서버 안내문 첫 줄로, 일을 시작할 때는 start-job 절차(문제·목표·조건 맞추기 → 기존 자료 먼저 → 진행 방식 고르기)를 따르게 한다.
2. **작업 주제와 현재 작업** — 일을 대화가 아니라 작업 세션(이어지는 큰 일의 묶음, 목적은 `context.md`)과 작업 브랜치(그 안에서 열고 닫히는 한 번의 일)로 나눈다. 대화는 그중 하나에 붙어 일하고, 여러 대화가 같은 작업 브랜치를 잇는다.
3. **히스토리** — 결과와 결정이 기록과 할 일로 쌓인다. 새 대화·/clear·압축 뒤에도 하던 일(목적, 열린 작업 브랜치와 그 다음, 할 일, 최근 흐름)이 자동으로 들어온다. 작업 브랜치는 끝낼 때 정리 하나로 메인에 합친다.
4. **대화 사이 메시지** — 살아 있는 대화들을 작업 세션·작업 브랜치 아래에 묶어 보고, 대화끼리 말을 전한다.

붙는 앱: Claude Code · Codex(터미널·데스크톱 앱) · Antigravity CLI(`agy`, ACP — 0.9.11부터, 패키지 루트 `plugin.json`·`hooks.json`·`mcp_config.json`이 같은 `skills/`를 싣는다). Antigravity의 깨우기와 서브에이전트 판정은 agy의 공개되지 않은 내부 통로·파일에 기댄다. 판정 근거를 못 찾으면 사람 대화로 다루고, 쓰기 거절은 남는다. OpenCode용 코드(`hosts/opencode/`)도 있지만 이 패키지의 포장(manifest)에는 없고, Claude Code 기준만큼 맞춰지지 않았다(코드 주석). 앱이 달라도 같은 기록을 읽고 쓰고, 앱을 넘어 말을 전한다.

## 지키는 모습

- 파일이 원본이다(`sessions/<이름>/…`). 색인(`.head/index-v5.sqlite`, 0.9.10)은 깨지거나 스키마가 다르면 파일에서 다시 만든다. 옛 판의 색인 파일은 읽지도 지우지도 않는다.
- 상주 프로세스가 없다: 도구 호출 때만 도는 도구 서버와 훅뿐이다. Node 내장 모듈만 쓴다(색인은 Node 내장 `node:sqlite`, 그래서 Node 22.13 이상이 필요하고 그보다 옛 Node에서는 이유 한 줄만 낸다).
- 현황판·폰 화면 같은 것은 코어 밖(추가기능)이다. 코어는 데이터(`claudeTree`)만 내준다.
- 사용자가 직접 치는 명령은 두지 않는다. 사람은 말하고, 도구는 에이전트가 부른다(README).
- 플러그인이 내는 안내·결과·오류 문구는 한국어다. 코어 지침 본문과 압축 지시(호스트의 요약 모델이 읽음)는 영어다.
