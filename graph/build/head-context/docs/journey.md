# 유저 저니맵 — head-context 0.9.10

통합(C-2): 단계·떠나는 곳은 처음 온 유저처럼 써 본 기록(A-3)으로 고쳤다. 코드만 보고 쓴 추정(B-7)은 발견·이탈 이유를 비워 두었다.

## 누구이고 어떤 상황인가

자기만의 LLM 사용법이 없는 AI 입문~중간 사용자. Claude Code나 Codex로 며칠~몇 주 이어지는 일을 하는데, 대화가 길어지면 압축되고 새 대화를 열면 하던 일을 다시 설명해야 한다. 이 사람의 agent가 플러그인을 직접 쓰고, 사람은 말로 시킨다.

## 단계

| 단계 | 원하는 것 | 하는 유저 활동 | 떠나는 곳 |
|---|---|---|---|
| 1. 알게 됨 | 압축·새 대화 뒤에도 일이 이어지기 | (제품 밖) 마켓 저장소 README·소개 글을 보고 설치 명령을 친다 | 설치 명령이 낯섦(설정만으로는 안 올라오고 README의 설치 명령이 필요함) |
| 2. 처음 붙임 | 빨리 쓸 준비 | `ua.first-run` | Codex 훅 신뢰를 모름(도구만 보이고 아무 글도 안 들어옴) |
| 3. 첫 일 | 말한 대로 일이 시작되기 | `ua.start-job` → `ua.pick-session` → `ua.branch` → `ua.record` | 작업 세션·작업 브랜치 개념이 낯섦. 시험에서 agent가 정해진 규칙을 어긴 일이 한 번씩 있었음: 맞추기 전에 바로 고침, 묻지 않고 작업 세션에 붙임, 사람 말 전에 작업 브랜치를 닫음(A-3) |
| 4. 이어 가기 | 다시 설명하지 않기 | `ua.resume` → `ua.look-back` → `ua.record` → `ua.todo` | 저장하지 않은 결정은 직전 주고받기에만 남아 그 뒤로 밀리면 잃음. 그때의 판단 맥락은 기록에 없음(A-3) |
| 5. 넓혀 쓰기 | 여러 대화·앱을 같이 쓰기 | `ua.delegate`, `ua.conversations` → `ua.message` | 대화 고르기가 헷갈림 |
| 6. 떠남 | — | 플러그인을 끄거나 프로젝트를 떠난다. 기록은 프로젝트 `.head/`에 파일로 남는다 | — |

## 돌아오는 계기

- 며칠 뒤 같은 프로젝트에서 새 대화를 열면 시작 훅이 하던 일을 다시 넣는다(`ua.resume`).
- 새 판이 나오면 초기설정이 적은 자동 업데이트로 앱 시작 때 받는다.
