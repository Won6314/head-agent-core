# 유저플로우 기획서 — head-context 0.9.15

> 0.9.5 판(11-04)을 0.9.10에 맞춰 바뀐 곳만 고쳤다(11-15). 0.9.15(11-23)에서 Antigravity 분기를 더했다. Antigravity 줄은 agy 없이 훅·도구 서버를 직접 돌린 출력(R159~R220)과 코드, 실측 기록으로 썼고, 처음 온 유저 시험은 하지 않았다. `A-3`·`C-3` 줄은 0.9.5에서 한 처음 온 유저 시험이고 0.9.10에서 다시 하지 않았다. 그 뒤 판에서 바뀐 것은 그 줄 끝에 적었다.

활동마다 절 하나가 기획서 하나다. 사람(👤)은 말하고, agent(🤖)가 도구를 부르고 출력을 읽는다. 차례의 각 단계는 그 단계가 일어나는 화면요소 ID를 적었다([화면설계서](screens.md)).
자르는 기준: 문제(조작을 고르기 전에 느끼는 상황)와 목표(대상에 하려는 일)가 둘 다 같으면 하나.
통합(C-2, 11-04): 화면만 보고 쓴 추정(A-4)과 코드만 보고 쓴 추정(B-7)을 합쳤다. 유저 쪽 글은 처음 온 유저처럼 써 본 기록(A-3, `missing-steps/a3/`)을, 구현 사실은 코드를 기준으로 했다. `실제와 다름`은 정해진 규칙을 시험에서 agent가 어긴 곳이고, 그 시험 한 번의 사실로 적는다(경향이 아니다). `관찰`은 규칙 위반이 아닌 사실이다.
반영(C-4, 11-04): 이 통합본만 보고 마켓 설치 경로로 활동 11개를 써 본 결과(C-3, `missing-steps/c3.md`: 글대로 됨 8, 일부 3, 안 됨 0)를 `C-3` 줄로 더했다.

## ua.first-run 프로젝트에 처음 붙여 초기설정을 한다

- 무엇을 하는가: 이 프로젝트에서 코어 지침과 자동 업데이트를 켠다.
- 문제: 플러그인을 깔았는데 이 프로젝트에서는 코어 지침도 기본 포크도 자동 업데이트도 꺼져 있다.
- 목표: 이 프로젝트에서 플러그인을 쓸 준비를 마친다.
- 언제: 설치 뒤 그 프로젝트에서 처음 대화를 열 때. Codex는 그 전에 훅 신뢰를 한 번 해야 한다.
- 차례:
  1. 🤖 시작 때 첫 실행 안내를 받는다 `STA-03#2`.
  2. 🤖 사람의 첫 입력에 답하기 전에 "초기설정 해도 될까요?"를 묻는다 `STA-03#2`.
  3. 분기 — 👤 예: 🤖 setup을 부르고 결과와 코어 지침 본문을 받아 이 대화부터 따른다 `TOL-12#1` `TOL-12#2` `TOL-12#3`.
  4. 분기 — 👤 아니오: 🤖 "다시는 묻지 않을까요?"를 묻고, 예면 never_ask를 기록한다 `TOL-12#4`.
  5. 분기 — Codex에서 훅 신뢰 전: 도구를 부르면 신뢰 경로를 받고 사람에게 전한다 `ERR-03#1` `ERR-03#2`.
  6. 분기 — Antigravity: `agy plugin install` 뒤 첫 시작에 같은 첫 실행 안내를 받는다(Antigravity 문구, R159) `STA-03#2`. setup 결과는 Antigravity 문구다 `TOL-12#6`. 훅이 돌기 전 대화의 도구 호출은 프로젝트를 모른다 `ERR-03#3`.
  7. 끝: 🤖 사람의 원래 이야기로 돌아간다.
- 얻는 것: 다음 시작부터 코어 지침이 들어가고(`STA-01#1`), `.claude/settings.json`에 기본 포크·마켓 자동 업데이트·플러그인 켜기 중 빠진 키가 채워진다. 이미 다른 값(예: false)이 있거나 JSON이 깨졌으면 바꾸지 않으므로 켜지지 않을 수 있고, 결과에 그렇게 적힌다. 사람은 "안녕" 한마디에 설정 질문을 한 번 받고, 동의하면 바로 원래 이야기로 돌아간다(A-3).
- 다음 활동: `ua.start-job`
- 관찰: 프로젝트 설정만 둔 시작에는 플러그인이 올라오지 않았고, README의 설치 명령을 친 뒤 올라왔다(A-3·C-3). 설치 절차는 README에 있다.
- 관찰: 한 프로젝트에서 대화 둘을 거의 같이 열면 둘 다 초기설정을 물었다(A-3 ua.message, 0.9.5). 0.9.10에서도 둘 다 묻는 것은 그대로이고, 늦게 승인한 쪽은 설정 파일을 잠그고 고치며 이미 초기설정됐다고 알린다 `TOL-12#5`.
- C-3: 프로젝트 설정을 쓴 뒤 설치 명령(`claude plugin install … --scope project`)을 치면 플러그인이 올라왔고, 동의·거절·never_ask·새 대화에서 다시 묻지 않음까지 글대로 됐다. 설치 명령 없이 설정만 둔 A-3에서는 올라오지 않았으므로, 처음 붙일 때는 설치 명령이 필요하다.


## ua.start-job 일을 시작하기 전에 문제·목표·조건과 일할 자리를 맞춘다

- 무엇을 하는가: 일을 받으면 만들기 전에 사람과 문제·목표·조건, 기록할 자리, 진행 방식을 정한다.
- 문제: 요청을 받자마자 만들면 이미 있는 자료를 놓치고 엉뚱한 범위로 간다.
- 목표: 일의 문제·목표·조건과 일할 자리(작업 세션·작업 브랜치), 진행 방식을 정한다.
- 언제: 계획·변경·도구·절차·위임이 될 일을 받았을 때.
- 차례:
  1. 🤖 서버 안내문 첫 줄에서 start-job을 먼저 부르라는 말을 읽는다 `SRV-01#1`. 0.9.5 코어 지침에도 같은 말이 있었으나 0.9.10 코어 지침(STA-01)에는 없다.
  2. 🤖 start-job 스킬을 불러 절차를 받는다 `SRV-03#2`. Antigravity도 같은 `skills/`를 싣고, 서버 안내문은 시작 훅으로 받는다(R159). 실제 agy에서 이 활동을 끝까지 써 본 기록은 없다.
  3. 🤖 기존 기록을 먼저 찾는다 `TOL-08#3` `TOL-09#1`.
  4. 🤖 start-job 차례대로 사람과 문제·목표·조건을 맞춘다 `SRV-03#1` `SRV-03#3`.
  5. 🤖 작업 세션이 없으면 고르거나 만든다 `TOL-01#1` `CMN-01#3`.
  6. 🤖 이어질 일이면 작업 브랜치를 열고 맞춘 것을 첫 기록으로 남긴다 `CMN-01#3` `TOL-03#1`.
  7. 끝: 🤖 직접 할지, 포크·에이전트에 맡길지 고른다 `SRV-03#4`.
- 얻는 것: 합의가 첫 기록으로 남고, 다음 대화가 그것을 이어받는다. 짧게 끝날 일이면 작업 브랜치는 열지 않아도 된다(맞추기는 한다).
- 다음 활동: `ua.pick-session`, `ua.branch`, `ua.delegate`
- 실제와 다름(A-3 ua.start-job, 한 번, 0.9.5): 그때 코어 지침은 일을 시작하면 start-job을 먼저 부르고 그 차례대로 하라고 정한다. agent는 start-job을 부르고 목록을 본 뒤, 문제·목표·조건을 사람에게 보이지 않고 위치·문구를 스스로 정해 파일을 바로 고쳤다. C-3에서는 차례대로 맞춘 뒤 시작했다.
- C-3: 글을 읽은 agent는 start-job을 먼저 부르고, 목록을 본 뒤 초안 없이 질문으로 맞추고, 사람 확인 뒤 작업 세션·작업 브랜치·첫 기록을 만들었다. A-3과 달리 건너뛰지 않았다. 여러 질문이 한 번에 긴 답으로 나왔다.


## ua.pick-session 이 대화를 이어지는 일(작업 세션)에 붙인다

- 무엇을 하는가: 대화가 어느 일의 기록을 읽고 쓸지 정한다.
- 문제: 이 대화가 어느 일의 기록을 쓰고 읽을지 정해지지 않았다.
- 목표: 대화를 작업 세션의 메인(또는 작업 브랜치)에 묶는다.
- 언제: 연결 안 된 대화에서 이어질 일이 시작됐을 때.
- 차례:
  1. 🤖 연결 안 됨을 본다 `STA-03#1`.
  2. 🤖 작업 세션 목록을 본다 `TOL-01#1` `TOL-01#2`.
  3. 분기 — 맞는 것이 있음: 🤖 사람에게 확인하고 불러온다 `SRV-01#2` `CMN-01#3`. 사람이 이름을 말했으면 그 이름으로 바로 불러온다.
  4. 분기 — Antigravity에서 클라이언트(모바일챗 등)가 시작 파일을 둠: 고르기 없이 그 작업 세션(·작업 브랜치)에 연결된 채 시작한다(`pol.agy-start-file`, R161·R162) `CMN-01#1`. 없는 작업 세션이면 실패 한 줄이 나온다 `ERR-04#3`.
  5. 분기 — 없음: 🤖 사람과 목적을 정하고 만들지 물은 뒤 만든다. 목적이 비면 거절된다 `ERR-01#2` `CMN-01#3`.
  6. 끝: 작업 맥락을 받는다 `CMN-01#1` `CMN-02#3`.
- 얻는 것: 이 대화의 저장·할 일이 그 작업 세션으로 가고, 이 대화를 잇는 대화(/clear, 복사본)도 같은 자리를 이어받는다.
- 다음 활동: `ua.branch`, `ua.record`
- 실제와 다름(A-3 ua.pick-session, 한 번): 서버 안내문은 '목록에서 맞는 것을 찾아 사용자에게 묻고 불러온다'고 정한다. agent는 목록·둘러보기를 본 뒤 사람에게 묻지 않고 작업 세션과 작업 브랜치를 불러왔다.
- A-3에서 사람이 얻은 것: 결정을 다시 묻지 않고 남은 결정 두 가지로 바로 넘어갔다. 그때의 판단 맥락(후보를 검토했는지)은 기록에 없어 되살아나지 않았다.
- C-3: 사람이 이름을 말한 새 대화에서 확인 없이 불러왔고(글대로), 목적을 정한 뒤 만들었으며, 빈 목적은 거절됐다. 이름 없이 후보 하나를 추천받는 분기는 시험하지 않았다.


## ua.resume 대화가 새로 열리거나 지워지거나 압축된 뒤 하던 일로 돌아온다

- 무엇을 하는가: 사람이 다시 설명하지 않아도 하던 일의 맥락을 되찾는다.
- 문제: 새 대화를 열거나 /clear·압축하면 모델이 하던 일을 잊는다.
- 목표: 목적, 열린 일, 할 일, 최근 흐름, 직전 대화를 되찾는다.
- 언제: 시작·/clear·압축 뒤. 재개·포크로 열면 이미 들고 있어 작업 세션·작업 맥락을 넣지 않는다(예외: Claude 재개에서 그 대화 기록에 코어가 없으면 코어를 한 번, 연결 안 된 대화면 연결 안 됨 한 줄, 바로잡은 기록 알림).
- 차례:
  1. (압축 전) 호스트 요약이 한 줄 포인터로 바뀐다 `CMP-01#1` `CMP-01#2`.
  2. 🤖 시작 때 코어 지침 `STA-01#1`(0.9.10 코어는 한 출력이라 둘째 출력은 비어 있다), 작업 세션 `CMN-01#1`, 작업 맥락 `CMN-02#1` `CMN-02#3`을 받는다.
  3. 분기 — Claude에서 압축·/clear 직후: 직전 주고받기 원문도 받는다 `STA-05#2`. Codex는 /clear 뒤 이어받지 않고 연결 안 됨으로 시작한다.
  4. 분기 — 이어받을 자리를 못 찾음: 연결 안 됨을 받는다 `STA-03#1`.
  5. 분기 — 깨진 기록을 옮겨 둠: 알림 한 줄을 받는다 `CMN-03#1`.
  6. 분기 — Antigravity: `session/load` 재개는 새 CHECKPOINT가 없으면 코어·작업 맥락을 다시 넣지 않는다. 편지함 메시지와 기록 알림은 따로 나온다. `/compact` 단계에 압축 지시를 받고 `CMP-01#1`, 새 CHECKPOINT가 보인 첫 단계에 코어·작업 세션·작업 맥락·최근 대화 원문을 한 번 받는다(R167~R169) `STA-01#3` `CMN-01#1` `STA-05#2`. 연결이 없으면 연결 안 됨 한 줄이다 `STA-03#1`. `/clear`는 없다. 서브에이전트는 압축 지시를 받지 않고, 압축 뒤에는 대화 안 작업 안내 하나만 받는다(R197·R198) `AGT-01#1`.
  7. 분기 — node:sqlite를 쓸 수 없는 Node: 작업 세션 대신 이유 한 줄을 받고(코어 지침·최근 대화는 들어옴), 사람에게 node를 바꾸라고 전한다 `ERR-05#1` `ERR-05#2`.
  8. 끝: 🤖 이 작업 브랜치의 최근 기록과 마지막 다음으로 이어서 한다 `CMN-02#4` `CMN-02#1`.
- 얻는 것: 작업 맥락이 9,000자를 넘으면 정해진 순서로 줄여서 들어오고 끝을 자르지 않는다. 열린 작업 브랜치, 할 일, 마지막 다음은 늘 남는다(0.9.6부터, R122). 작업 맥락 맨 위에 작업 세션 폴더 줄이 있다 `CMN-01#4`. 전문은 지난 기록 읽기로 본다.
- 다음 활동: `ua.look-back`, `ua.record`
- A-3에서 사람이 얻은 것: 대화형 Claude에서 /clear 뒤 새 대화가 같은 작업 세션·작업 브랜치를 이어받아, 도구를 부르지 않고 작업·다음 할 일을 답했다. 압축 뒤에도 같았다. 저장하지 않은 결정(문구·색)은 자동으로 붙은 직전 주고받기 원문으로만 살아남았고, agent는 기록된 것과 안 된 것을 나눠 답했다(A-3 ua.resume).
- C-3: 실제 /clear·압축 뒤 도구를 부르지 않고 작업 세션·작업 브랜치·결정·다음과 직전 주고받기의 내용을 답했다.


## ua.branch 한 번의 일을 작업 브랜치로 열고, 잇고, 끝맺는다

- 무엇을 하는가: 일 하나를 이름 붙여 열고, 여러 대화가 잇고, 끝나면 정리 하나로 메인에 합친다.
- 문제: 같은 작업 세션 안에서 여러 일의 경과가 한 흐름에 섞인다.
- 목표: 한 번의 일을 따로 열고 끝맺는다.
- 언제: 작업에 착수할 때, 이어 갈 작업 브랜치가 작업 맥락에 있을 때, 일이 끝났거나 그만둘 때.
- 차례:
  1. 🤖 이름을 주고 연다. 그 작업 브랜치의 작업 맥락을 받는다 `CMN-01#3`.
  2. 분기 — 다른 대화가 같은 일을 이음: 이어 간다(attach) `CMN-01#3`.
  3. 분기 — 다른 작업 브랜치로 옮김: 떠난 것은 열린 채 남는다 `CMN-02#1`.
  4. 끝 — 👤가 끝났다고 함: 다음 없이 저장하고 정리(recap)를 준다. 메인에 합쳐지고 대화는 메인으로 간다 `TOL-03#4`. 정리가 없으면 거절된다 `ERR-01#3`.
  5. 끝 — 👤가 그만둠: 이유와 함께 중단한다 `TOL-03#5`. 이유가 없으면 거절된다 `ERR-01#5`.
  6. 분기 — 이름에 띄어쓰기: 거절된다 `ERR-01#8`. 이름이 달 꼴(`2026-11`)이어도 거절된다 `ERR-01#12`.
