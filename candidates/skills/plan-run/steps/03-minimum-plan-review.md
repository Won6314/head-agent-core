# 03 — P0의 계획 필요 최소성 점검

현재 전체 기준 `P0_ID`에서 분기한다. 세부 검증보다 먼저, 이 계획 자체가 필요한지 본다.

## 호출 — context_run

```json
{
  "source_id": "{P0_ID}",
  "command": "너는 전체 목표를 보존한 P0에서 이미 포크된 전체 계획 점검 세션이다. 지금 {PLAN_FILE}을 보고, 이것이 전체 목표에 도달하기 위해 정말 필요한 최소의 계획인지 판단하라. 쓸데없는 규격화·절차·도구·작업을 늘리거나 수단 자체가 목적이 된 부분은 없는지 보라. 무엇을 덜어내거나 바꿔야 하는지, 무엇은 목표를 위해 필요한지와 그 이유를 {P0_PLAN_REVIEW_FILE}에 정리하라. 일반적인 실행 규격 검증은 이어지는 Pn이 맡는다.",
  "completion_note": "현재 단계: P0 계획 필요 최소성 점검. 다음 처리: 판정에 따라 계획 보완 또는 Pn 계획 검증. 레퍼런스: plan-run / steps/03-minimum-plan-review.md."
}
```

## 알림을 받으면

- 보완이 필요하면 [02의 제작 맥락](02-execution-planning.md)에 이유를 전달한다. 변경된 계획은 새 검토 대상으로 취급한다.
- 준비됐으면 계획과 P0 점검 참조를 [04 Pn 계획 검증](04-plan-acceptance.md)에 전달한다.
- 전체 목표·조건을 바꾸는 결정은 사용자에게 돌린다.
