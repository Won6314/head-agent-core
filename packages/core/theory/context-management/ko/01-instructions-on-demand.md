# 필요한 작업 지침만 불러오는 방법

[목차](README.md) · [English](../01-instructions-on-demand.md)

## 지침도 컨텍스트다

LLM에게 작업 지침은 선택 사항이 아니다. 무엇을 해야 하는지, 어떤 기준을 지켜야 하는지, 어디까지 판단할 수 있는지를 지침이 정한다.

문제는 지침이 많아질 때 생긴다. 개발, 조사, 디자인, 배포, 데이터베이스, 커뮤니케이션을 위한 지침을 모두 하나의 프롬프트에 넣으면 모델은 현재 작업과 관계없는 규칙까지 매번 함께 받는다.

```text
메인 지침
+ 개발 지침
+ 조사 지침
+ 디자인 지침
+ 배포 지침
+ 데이터베이스 지침
+ 그 밖의 모든 지침
```

이 방식은 처음에는 단순해 보인다. 하지만 기능과 작업 종류가 늘어날수록 지침은 계속 길어진다. 서로 다른 상황을 위해 작성된 규칙이 같은 공간에서 경쟁하고, 지금 중요한 한 문장이 수많은 예외 사이에 묻힌다.

지침도 많이 넣는다고 항상 더 안전하거나 정확해지는 것은 아니다. 관계없는 지침은 모델이 해석해야 하는 또 하나의 컨텍스트다.

## 하나의 메인 지침과 여러 개의 작업 지침

대안은 모든 지침을 더 짧게 요약해 한곳에 넣는 것이 아니다. 지침의 역할을 나누는 것이다.

```text
메인 지침
+ 작은 지침 인덱스
+ 현재 작업에 필요한 상세 지침
```

메인 지침에는 여러 작업에서 변하지 않는 원칙만 둔다.

- 전체 결과를 먼저 이해한다.
- 사용자가 소유한 중요한 결정을 임의로 바꾸지 않는다.
- 현재 결과를 바꿀 수 있는 컨텍스트만 가져온다.
- 실제 결과와 근거를 확인한다.
- 작업의 종류에 따라 필요한 절차를 선택한다.

반면 특정 상황에서만 필요한 내용은 별도의 작업 지침으로 분리한다.

- 소프트웨어를 변경할 때 확인할 것
- 장기 계획을 만들고 실행할 때의 절차
- 배포 전후에 확인할 것
- 특정 도구나 외부 서비스를 사용하는 방법
- 하나의 결과를 다른 작업자에게 맡기는 방법

이렇게 하면 메인 지침은 작고 안정적으로 유지되고, 상세 지침은 필요한 순간에만 컨텍스트에 들어온다.

## 인덱싱도 노이즈지만 훨씬 작다

필요한 지침을 찾으려면 어떤 지침이 존재하는지 알려주는 인덱스가 필요하다. 인덱스 역시 컨텍스트를 차지하므로 비용이 전혀 없는 것은 아니다.

하지만 두 비용의 크기는 다르다.

```text
모든 지침의 전체 내용을 항상 넣는 비용
≫
어떤 지침을 언제 가져올지만 알려주는 비용
```

인덱스에는 상세 절차가 아니라 관계만 있으면 된다.

```text
소프트웨어 변경 → 개발 작업 지침
단일 결과 위임 → 단일 위임 지침
장기 작업       → 계획과 Run 지침
배포            → 배포 지침
```

현재 요청이 어떤 작업인지 판단하면 연결된 지침만 가져온다. 인덱싱에서 생기는 작은 노이즈를 감수하는 대신, 관계없는 지식 전체가 항상 들어오는 큰 노이즈를 제거하는 구조다.

## 지침을 검색하는 것과 지침을 따르는 것은 다르다

인덱스는 어떤 지침이 관련 있는지 찾는 역할만 한다. 실제 행동을 정하는 것은 선택된 지침의 현재 내용이다.

이 구분이 필요한 이유는 인덱스가 오래될 수 있기 때문이다. 연결이 잘못되었거나 지침이 이동했을 수도 있다. 따라서 인덱스는 탐색 경로이고, 선택된 현재 지침이 실제 작업의 근거가 된다.

```text
요청
  ↓
작업 유형 판단
  ↓
관련 지침 탐색
  ↓
현재 지침 확인
  ↓
작업 수행
```

## HEAD Core에서 볼 수 있는 형태

HEAD Core는 모든 세부 절차를 하나의 거대한 지침에 넣지 않는다.

`HEAD_CORE.md`는 전체 결과, 권한, 컨텍스트, 실행 방식과 증거에 관한 공통 원칙을 제공한다. 소프트웨어 변경, 단일 위임, 장기 계획, Run 실행과 같은 구체적인 절차는 각각의 Skill로 분리된다.

```text
HEAD Core
= 공통 원칙 + 작업 유형 판단 + 지침 라우팅

Skills
= 현재 작업에서만 필요한 상세 절차
```

예를 들어 소프트웨어 동작을 바꾸는 요청에서는 개발 작업을 형성하는 지침을 불러오고, 독립적인 하나의 결과를 맡길 때는 단일 위임 지침을 불러온다. 두 작업과 관계없는 절차는 현재 컨텍스트에 들어올 필요가 없다.

이 구조의 목적은 지침을 숨기는 것이 아니다. 필요한 지침을 더 정확하게 보이게 하는 것이다.

## 어디까지 나눠야 하는가

모든 문장을 별도의 지침으로 나누면 오히려 탐색 비용이 커진다. 다음 기준이 유용하다.

- 여러 작업에 항상 필요한 원칙은 메인 지침에 둔다.
- 특정 작업 유형에서만 필요한 절차는 분리한다.
- 작고 자주 함께 사용되는 지침은 하나로 유지한다.
- 선택 기준을 설명하기 어려울 정도로 잘게 나누지 않는다.

중요한 것은 파일 수가 아니라 현재 작업에 들어오는 컨텍스트의 밀도다.

## 결론

작업 지침을 정제한다는 것은 모든 지침을 짧게 압축해 하나의 프롬프트에 넣는 일이 아니다.

> 하나의 메인 지침에는 공통 원칙과 탐색 방법만 두고, 상세 지침은 현재 작업과의 관계에 따라 불러온다.

이제 지침 다음에 필요한 것은 문제를 이해하기 위한 자료다. 다음 글에서는 [문서와 검색 결과를 그래프로 정제하는 방법](02-graph-research-context.md)을 살펴본다.
