# LLM 컨텍스트 관리

[English](../README.md)

## 컨텍스트가 곧 실제 성능이다

LLM은 현재 주어진 컨텍스트를 바탕으로 다음 결과를 만든다. 모델이 아무리 뛰어나도 필요한 정보가 보이지 않으면 사용할 수 없고, 관련 없는 정보가 많이 섞이면 무엇에 집중해야 하는지가 흐려진다.

그래서 실제 LLM 시스템의 결과는 모델만으로 설명되지 않는다. 다음 식은 정확한 수학 공식이 아니라, 같은 모델도 컨텍스트에 따라 전혀 다르게 작동한다는 실용적인 근사다.

```text
실제 작업 결과
≈ 모델의 추론 능력 × 현재 컨텍스트의 품질
```

여기서 컨텍스트의 품질은 단순한 정보량이 아니다. 현재 작업에 필요한 정보가 선택되어 있고, 서로의 관계가 드러나며, 이미 끝난 과정과 무관한 정보가 빠져 있는 상태를 말한다.

> LLM을 잘 작동시키는 일은 결국, 지금 무엇을 보게 할 것인가를 결정하는 일이다.

## 작업 컨텍스트의 네 단계

LLM이 긴 작업을 수행할 때 필요한 컨텍스트는 크게 네 단계로 흐른다.

```text
1. 작업 지침
        ↓
2. 이해와 조사
        ↓
3. 해결 계획
        ↓
4. 작업 실행과 진행 상황
```

각 단계의 결과는 다음 단계의 입력이 된다. 따라서 앞 단계에서 들어온 노이즈와 누락은 뒤 단계로 전달되고, 때로는 더 그럴듯한 형태로 증폭된다.

## Context Window는 집중력과 다르다

Context Window는 모델이 한 번에 받을 수 있는 최대 정보량이다. 그러나 그 안의 모든 내용을 같은 수준으로 활용한다는 뜻은 아니다.

```text
Context Window ≠ Effective Context
```

창고가 커졌다고 작업대가 자동으로 정리되는 것은 아니다. 불필요한 정보, 비슷한 설명, 오래된 결정과 반복된 기록이 함께 들어오면 모델이 핵심 정보를 선택하고 관계를 해석해야 하는 부담도 커진다.

따라서 좋은 컨텍스트 관리는 창을 최대한 채우는 일이 아니다. 다음 판단을 바꿀 수 있는 정보를 충분히 제공하면서, 그 밖의 노이즈는 가져오지 않는 일이다.

## 노이즈는 질문에 따라 달라진다

노이즈는 틀린 정보만을 의미하지 않는다. 사실이라도 현재 질문에 필요하지 않으면 그 순간에는 노이즈가 될 수 있다.

```text
노이즈
= 현재 판단에 필요하지 않은 정보
```

그러므로 모든 작업에 공통으로 사용할 수 있는 완벽한 거대 프롬프트는 만들기 어렵다. 좋은 컨텍스트는 미리 완성된 하나의 문서가 아니라, 작업 단계와 현재 질문에 따라 계속 새로 구성되는 작업 입력이다.

## 하나의 공통 원리

네 단계는 서로 다른 기술을 사용하지만 같은 방향을 가진다.

```text
모든 것을 항상 넣는다
        ↓
관련 없는 정보와 과정이 누적된다

현재 필요한 것만 선택한다
        ↓
작고 밀도 높은 컨텍스트를 구성한다
```

이 자료는 특정 모델의 내부 인지 과정을 설명하는 과학 이론이 아니다. 실제 LLM 작업에서 컨텍스트를 구성하기 위한 운영 모델이다. 작업의 규모와 위험이 작다면 모든 단계에 정교한 구조가 필요하지 않다. 중요한 것은 구조 자체가 아니라, 다음 판단을 더 깨끗한 입력 위에서 내릴 수 있게 하는 것이다.
