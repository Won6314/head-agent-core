# HEAD 시스템의 구성 요소

HEAD Core는 하나의 거대한 AI가 모든 일을 혼자 처리하는 구조가 아니다. 전체 결과를 책임지는 HEAD를 중심으로, 작업의 연속성을 보존하는 기록과 경계가 분명한 실행 역할을 연결한 시스템이다.

```text
User
  ↕ 방향, 질문, 중요한 결정
HEAD
  ├─ Session: 지속되는 작업 관계와 합의
  │   └─ Run: Plan을 Slice·Horizon·Checkpoint로 진행
  ├─ Skill ──(필요한 경우)──> Procedure
  │     현재 상황에 맞는 작업 흐름과 조건별 세부 절차
  └─ Agent: 경계가 정해진 결과의 실행 또는 검토

Coordination Host
  └─ Agent 작업, 메시지와 실행 상태를 프로젝트별로 관리
```

## User

User는 시스템이 만들어야 할 결과의 방향을 정하는 사람이다.

다음과 같은 중요한 결정은 사용자에게 남는다.

- 제품과 프로젝트의 방향
- 중요한 정책과 사용자 경험
- 중요한 아키텍처와 비용 선택
- 작업 방식에 관한 중대한 변경
- 배포, 게시, 결제 같은 중요한 외부 행동의 승인

사용자가 모든 구현 세부사항을 직접 결정해야 한다는 뜻은 아니다. 방향과 중요한 경계를 정하면, HEAD와 각 실행 역할이 그 안에서 일반적인 실무 판단을 맡는다.

## HEAD

HEAD는 전체 결과의 조정자이자 최종 통합 책임자다.

HEAD는 다음을 하나의 연결된 이해 안에서 유지한다.

- 사용자가 원하는 결과
- 현재 상태와 원하는 상태
- 기준이 되는 출처와 이미 정해진 결정
- 중요한 구성 요소 사이의 관계
- 다음에 만들어야 할 완결된 결과
- 그 결과가 실제로 성립했음을 보여 줄 근거

HEAD는 직접 작업, 한 번의 위임, 지속적인 Run 중 적절한 방식을 선택한다. Agent에게 실행을 맡기더라도 전체 목표와 중요한 판단, 결과의 수용 여부는 HEAD에 남는다.

HEAD가 항상 옳다는 뜻은 아니다. HEAD 역시 의도를 오해하거나 근거를 잘못 선택할 수 있다. 책임을 한곳에 둔다는 것은 오류가 없다는 뜻이 아니라, 어떤 목표와 근거로 판단했는지 추적하고 바로잡을 주체가 분명하다는 뜻이다.

## Session

Session은 **하나의 지속적인 사용자–HEAD 작업 관계와 합의**를 보존하는 단위다.

일반 대화 기록과 달리 Session은 “우리가 지금 어떤 일을 함께 하고 있는가”라는 정체성을 유지한다. 작업이 중단되거나 대화 내용이 압축되어도, 다음에 돌아왔을 때 같은 목적과 합의에서 이어갈 수 있게 한다.

Session에는 보통 다음과 같은 내용이 연결된다.

- 작업의 목적과 범위
- 현재까지 합의된 방향
- 진행 상태와 다음 행동
- 필요할 때 시작한 Run

모든 Session에 Run이 있는 것은 아니다. 직접 작업이나 한 번의 위임만으로 끝나는 작업도 Session 안에서 진행할 수 있다.

## Run

Run은 Session 안에서 **합의된 전체 계획을 여러 결과와 점검 지점으로 실행하기 위한 지속 단위**다.

Run은 단순한 할 일 목록이 아니다. 목표와 경계, 중요한 결정, 현재 위치와 점검 결과를 기준 기록으로 보존한다. 그래서 다음 실행 담당자는 전체 대화 기록을 다시 해석하지 않고도 자신이 맡은 정확한 결과를 수행할 수 있고, HEAD는 각 결과를 전체 계획에 다시 연결할 수 있다.

Run은 여러 의존 결과, 의미 있는 중간 점검 또는 중단 후 복구가 필요할 때 사용한다.

## Plan, Slice, Horizon과 Checkpoint

Run 안에서는 전체 계획과 현재 실행 단위를 구분한다.

### Plan

Plan은 사용자가 받아들인 전체 결과와 중요한 설계 결정이다. 실행 중 무엇이 맞는 결과인지 판단하는 기준이다.

### Slice

Slice는 한 실행 담당자가 독립적으로 완성할 수 있도록 현재 Plan에서 잘라낸 결과다. 필요한 입력, 고정된 결정, 변경 경계, 결과의 사용자와 확인 방법이 함께 정해진다.

Slice는 전체 Plan을 대신하지 않는다. 실행 담당자가 맡은 범위를 분명하게 보여 주는 현재 작업 계약이다.

### Horizon

Horizon은 현재 실행할 준비가 된 하나 이상의 결과 묶음이다. 서로의 결과를 기다리거나 같은 결정을 함께 바꿔야 하는 작업은 같은 시점에 독립 실행하지 않는다.

### Checkpoint

Checkpoint는 Horizon의 실제 결과를 Plan에 다시 연결해 판단하는 지점이다. HEAD는 결과를 받아들일지, Plan 의미를 유지한 채 고칠지, 계획 변경이나 사용자 결정이 필요한지, 다음 결과로 진행할지를 정한다.

## Agent

Agent는 경계가 정해진 결과 하나를 맡는 전문 작업 역할이다.

Agent는 전체 프로젝트 방향을 새로 정하지 않는다. HEAD가 제공한 결과, 기준 출처, 고정 결정과 변경 경계 안에서 로컬 실행 방법을 선택하고, 산출물과 직접 근거를 반환한다.

기본 Core에는 세 가지 재사용 가능한 역할이 있다.

### Developer

Developer는 한 번의 위임으로 완성할 수 있는 구현 결과를 맡는다. 정해진 경계 안에서 소스를 조사하고, 구현하고, 문제를 고치고, 대표 결과를 확인한다.

### Coder

Coder는 Run에서 이미 충분히 결정된 Slice를 구현한다. 외부에서 관찰되는 Plan의 의미를 바꾸지 않고, 정해진 실행 결과를 코드와 상태로 만든다.

### Reviewer

Reviewer는 중대한 제품·정책·아키텍처·비용 또는 여러 결과에 걸친 결정을 구현 전에 독립적으로 평가한다. 다른 관점에서 근거와 위험을 검토하지만, 구현하거나 프로젝트의 최종 방향을 스스로 결정하지는 않는다. 일반적인 구현 결과 검증이나 Run Checkpoint 판단과는 다른 역할이다.

프로젝트는 필요에 따라 별도의 전문 Agent를 추가할 수 있다. 이들은 Core의 공통 역할이 아니라 해당 프로젝트가 소유하는 확장이다.

## Skill

Skill은 HEAD가 현재 작업 종류에 맞는 **발견 가능한 상위 작업 흐름을 선택하는 진입점**이다.

예를 들어 소프트웨어 동작을 설계해야 하는 상황, 결과 하나를 위임하는 상황, 지속적인 Run을 진행하는 상황은 서로 다른 작업 흐름을 필요로 한다. HEAD는 현재 조건에 맞는 Skill만 불러와 사용한다.

Skill의 목적은 모든 지침을 항상 넣는 것이 아니다. 현재 판단과 실행에 필요한 흐름만 제때 제공하는 것이다.

## Procedure

Procedure는 선택된 Skill이 필요에 따라 연결하는, 특정 조건에 필요한 **내부 세부 절차**다. Procedure 자체는 별도의 상위 작업 흐름으로 발견되지 않는다.

예를 들어 Run을 시작하는 절차, 현재 Slice를 준비하는 절차, Checkpoint 결과를 반영하는 절차는 같은 Run 흐름에 속하지만 동시에 모두 필요하지는 않다. 세부 분기가 필요한 상태라면 현재 조건에 해당하는 Procedure만 선택해 읽는다. 모든 Skill이 반드시 Procedure로 이어지는 것은 아니다.

정리하면 Skill은 “지금 어떤 종류의 일을 하는가”를, Procedure는 “그 흐름의 현재 단계에서 무엇을 하는가”를 다룬다.

## Coordination Host

Coordination Host는 HEAD와 Agent 사이의 작업 실행과 메시지를 관리하는 사용자 범위의 실행 기반이다.

주요 역할은 다음과 같다.

- 프로젝트와 호출자의 경계를 확인한다.
- Agent 작업을 분리해 시작하고 추적한다.
- 작업 상태, 로그, 결과와 반환 위치를 관리한다.
- 완료 결과를 해당 작업을 시작한 HEAD에게 전달한다.
- 프로젝트별 작업과 메시지가 다른 프로젝트와 섞이지 않게 한다.

Host가 프로젝트의 목표나 결과를 판단하지는 않는다. 작업을 안전하게 실행하고 전달하는 기반이며, 의미와 수용 여부는 HEAD와 프로젝트의 권위에 달려 있다.

Core는 공통 Skill, 일회성 Agent 작업과 역할 메시지의 기반을 제공한다. 제품별 Skill, 전문 Agent, 외부 도구와 더 복잡한 작업 제어는 각 프로젝트가 필요에 따라 추가하는 확장이다.

## 구성 요소가 함께 움직이는 예

사용자가 “로그인 오류를 고치고 실제 로그인까지 확인해 달라”고 요청했다고 하자.

1. User가 원하는 결과와 중요한 제약을 정한다.
2. HEAD가 전체 로그인 흐름과 기준 출처를 이해하고 작업 방식을 선택한다.
3. Session은 이 작업의 합의와 현재 위치를 보존하고, 장기 실행이 필요하면 Run이 그 안에 만들어진다.
4. Agent 작업이 필요하면 HEAD가 경계를 정하고 Host가 해당 작업을 시작해 결과를 돌려준다.
5. HEAD는 반환된 산출물과 근거를 전체 로그인 흐름에 다시 연결해 완료 여부를 판단한다.

구성 요소가 많아 보여도 중심 원리는 단순하다. **User가 방향을 정하고, HEAD가 전체를 유지하며, Session과 Run이 합의를 보존하고, Agent가 경계가 정해진 결과를 만든다.**
