# HEAD Core란 무엇인가

## 30초 설명

HEAD Core는 AI가 긴 작업을 하면서도 **처음 합의한 목표와 중요한 맥락을 잃지 않도록 돕는, 프로젝트에 연결해서 사용하는 작업 환경**이다.

HEAD Core는 전체 결과를 조정하는 **HEAD 역할**, 중단 후에도 합의와 진행 상태를 이어가기 위한 기록, 경계가 분명한 일을 맡을 수 있는 전문 작업 역할을 함께 제공한다. 여기서 HEAD는 Core 안에서 사용자와 대화하며 작업을 이끄는 AI 역할이다.

사용자는 여러 작업 역할을 직접 지휘하는 대신 HEAD와 대화한다. HEAD는 요청의 전체 결과를 이해하고, 필요한 근거를 찾고, 알맞은 방식으로 일을 진행한 뒤, 나온 결과들이 원래 목표를 실제로 충족하는지 판단할 책임을 맡는다.

```text
사용자의 목표
  → HEAD가 전체 문제와 근거를 이해한다
  → 알맞은 방식으로 작업한다
  → 실제 결과를 확인한다
  → 전체 목표에 맞게 통합하고 완료를 판단한다
```

## 왜 필요한가

AI는 명확하게 주어진 한 단계의 작업을 빠르게 수행할 수 있다. 그러나 작업이 길어지고 여러 조사와 구현을 거치면 다음과 같은 문제가 생기기 쉽다.

- 처음 요청의 중요한 조건이 중간 결과에서 빠진다.
- 최근에 작성된 요약이나 계획이 원래 목표를 대신한다.
- 여러 작업자가 각자의 부분은 잘 만들지만 결과들이 하나로 맞물리지 않는다.
- 테스트나 작업 보고서는 성공했지만 사용자가 원한 실제 흐름은 완성되지 않는다.
- 대화가 중단되거나 압축된 뒤 이전의 합의와 현재 위치가 달라진다.

이 문제는 단순히 더 좋은 모델을 쓰거나 더 많은 정보를 한꺼번에 주는 것만으로 해결되지 않는다. 현재 판단에 필요한 올바른 정보가 선택되어야 하고, 중요한 결정과 목표가 작업 단계 사이에서 계속 유지되어야 한다.

HEAD Core는 이 책임을 하나의 조정 역할인 **HEAD**에 모은다.

## HEAD가 하는 일

HEAD는 하나의 작업만 수행하는 도구가 아니라 **전체 결과를 끝까지 관리하는 역할**이다.

HEAD는 보통 다음을 담당한다.

1. 사용자가 원하는 최종 결과를 이해한다.
2. 현재 판단을 좌우하는 문서, 코드, 데이터와 결정을 찾는다.
3. 무엇이 중요한 결정이며 누가 결정해야 하는지 구분한다.
4. 한 흐름에서 직접 처리할지, 독립된 결과 하나를 전문 작업 역할에 맡길지, 여러 단계의 지속 작업으로 진행할지 선택한다.
5. 작업 중 나온 결과와 근거를 원래 목표에 다시 연결한다.
6. 계획이나 보고서가 아니라 실제 결과를 기준으로 완료 여부를 판단한다.

HEAD가 모든 일을 직접 한다는 뜻은 아니다. 필요한 경우 전문 작업 역할인 **Agent**가 구현이나 검토처럼 경계가 분명한 결과 하나와 그 안의 로컬 수행·평가 방법을 맡는다. 다만 일을 맡긴 뒤에도 전체 목표를 이해하고 결과를 통합하는 책임은 HEAD에 남는다.

## 사용자는 어떻게 이용하는가

사용자는 내부 작업 방식이나 Agent를 일일이 지정할 필요 없이 원하는 결과를 HEAD에게 말한다.

예를 들면 다음과 같다.

- “이 오류의 원인을 찾고 고쳐줘.”
- “새 기능의 정책과 사용자 흐름을 설계해줘.”
- “이 계획대로 구현하고 중간 결과를 확인하면서 진행해줘.”
- “중단했던 작업을 이전 합의에서 이어가자.”

HEAD는 요청의 성격과 현재 상태를 보고 가장 작은 적절한 작업 방식을 선택한다. 한 흐름에서 끝낼 수 있으면 직접 처리한다. 독립된 결과 하나가 필요하면 Agent에게 한 번 맡긴다. 여러 결과와 중간 판단이 이어져야 하면 목표와 현재 위치를 기록하는 지속 작업인 **Run**으로 진행한다.

중요한 제품 방향, 정책, 아키텍처, 비용, 작업 방식에 관한 결정은 사용자에게 남는다. HEAD는 그 방향 안에서 일반적인 조사, 계획, 실행 전략, 통합과 완료 판단을 맡는다.

방향에 동의했다는 사실이 곧 모든 외부 행동을 허가한 것은 아니다. 배포, 게시, 결제처럼 중요한 외부 행동에는 사용자의 별도 결정이나 승인이 필요하다.

## 일반적인 AI 작업과 무엇이 다른가

HEAD Core가 중요하게 보는 것은 단순한 작업량이나 Agent 수가 아니다.

### 전체 결과를 맡는 주체가 있다

부분 작업이 여러 개여도 HEAD가 처음부터 끝까지 같은 전체 결과를 기준으로 판단한다.

### 필요한 맥락만 골라서 사용한다

모든 기록을 매번 쌓아 넣기보다, 현재 판단을 바꿀 수 있는 권위 있는 정보와 관계를 찾아 사용한다.

### 합의와 진행 상태를 대화 밖에 보존한다

오래 이어지는 작업 단위인 **Session**과, 그 안에서 여러 단계로 진행되는 **Run**은 대화와 별도로 유지되는 기준 기록에 목표, 결정과 현재 위치를 보존한다. 대화 요약이나 작업자의 보고가 원래 합의를 조용히 바꾸지 못하게 하기 위해서다.

### 결과를 실제 흐름으로 확인한다

계획 작성, Agent의 완료 보고, 개별 테스트 통과만으로 전체 작업이 끝났다고 판단하지 않는다. 가능한 경우 권위 있는 입력에서 실제 결과와 그 결과를 사용하는 대상까지 이어지는 대표 흐름을 확인한다.

## HEAD Core가 아닌 것

HEAD Core는 다음을 목표로 하지 않는다.

- 여러 자율 Agent가 각자 프로젝트 방향을 결정하는 군집 시스템
- 모든 작업을 무조건 분할하고 위임하는 시스템
- 사용자의 중요한 제품·정책·비용 결정을 대신하는 시스템
- 모든 프로젝트 지식과 기록을 하나의 거대한 프롬프트에 넣는 방식
- 테스트 수나 작업 체크리스트만으로 완료를 판정하는 방식

또한 HEAD Core 자체에는 특정 제품의 정책, 코드 지식, 자격 증명이나 배포 규칙이 들어 있지 않다. Core는 공통 작업 방식을 제공하고, 각 프로젝트가 자신의 문서, 저장소, 도구와 운영 규칙을 연결한다.

HEAD Core는 정확성을 보장하는 장치도 아니다. HEAD는 사용자의 의도를 잘못 이해하거나, 맞지 않는 근거를 선택하거나, 결과를 잘못 판단할 수 있다. 이 구조의 목적은 그런 가능성을 없애는 것이 아니라 중요한 목표와 근거, 판단 책임을 계속 드러내어 오류를 줄이고 바로잡을 수 있게 하는 것이다.

## 한 문장으로 다시 말하면

> HEAD Core는 AI 작업에서 전체 목표, 올바른 맥락, 실행 결과를 한 책임 아래 계속 연결해 주는 프로젝트 작업 운영 체계다.
