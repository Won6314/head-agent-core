# Developer One-Shot Branch

Use after `delegate-once` selects `developer` for one bounded implementation result.

## Contract

HEAD supplies the exact subset of its whole-outcome context needed to execute the result, compiled from the developer's available starting context. Material facts and relationships are stated or supplied through exact readable authority references rather than assumed from HEAD's private context. The developer performs local source inspection, implementation, correction, and proof inside that bounded context.

The bounded context states:

1. the required observable output or state and its acceptance boundary;
2. authoritative inputs and locked decisions;
3. the real consumer;
4. the exact mutation boundary;
5. the behavior and state to preserve; and
6. one representative proof from authoritative input to the consumed result.

The developer chooses local implementation details inside the contract and returns a bounded conflict when the result cannot be produced without changing a parent decision or boundary.

The contract names a prohibited implementation only when it is a plausible local choice that would materially violate the result, and pairs it with the required behavior.

## Return

The developer returns artifacts and direct evidence. HEAD reintegrates them into the whole-outcome context and judges the result.
