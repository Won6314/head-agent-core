# 일 시작하기

## 1. 문제를 파악한다
사용자의 요청과 대화를 읽고 무엇이 문제이고 어떤 결과를 원하는지 파악한다. 이미 정해진 것과 지켜야 할 조건도 확인한다. 뜻이나 범위가 분명하지 않으면 묻는다.

## 2. 기존 자료를 먼저 찾는다
작업 세션 기록과 프로젝트 파일에서 비슷한 자료·결정·도구를 찾는다. 있으면 그것을 쓰고 필요한 만큼 고친다. 정말 없을 때만 새로 만든다.

## 3. 문제·목표·조건을 맞춘다
- 문제(무엇이 안 되거나 부족한가), 목표(무엇을 가능하게 하려는가), 조건(이미 정한 것, 지킬 범위)을 짧은 불릿으로 보이고 사용자와 맞춘다. 이미 합의된 것은 다시 묻지 않는다.
- 맞춰지면 작업 세션과 작업 브랜치를 생각한다. 작업 세션이 없으면 맞추거나 만든다. 이어서 할 일이면 작업 브랜치를 열고, 맞춘 문제·목표·조건을 첫 기록으로 남긴다. 짧게 끝날 일이면 열지 않아도 된다.

## 4. 진행 방식을 고른다
일을 맡기면 이 대화는 그 일의 세부로 채워지지 않는다. 대신 맡은 쪽은 받은 만큼만 안다.
그래서 "이 일에 어떤 지식이 필요한가"와 "그 세부를 이 대화가 다시 쓰는가"로 고른다.

| 방식 | 조건 | 예시 |
|---|---|---|
| 직접 | 이 대화에서 바로 할 수 있고, 결과의 세부를 이어서 판단에 쓴다 | 방금 정한 문구로 파일 한 곳 고치기. 사용자와 목표를 맞추다가 사실 하나 확인하기 |
| 기본 포크 (Agent 도구, subagent_type "fork") | 이 대화에서 정한 것을 알아야 하고, 한 번에 끝나며, 결과만 받으면 된다 | 합의한 설계대로 구현하고 시험까지 돌리기. 합의한 용어로 문서 여러 곳 고쳐 쓰기 |
| 사이드 포크 (데스크톱) | 기본 포크와 같지만, 사용자가 따로 이어서 대화하며 진행할 일 | 합의한 기획 중 한 기능을 사용자와 따로 다듬기 |
| 에이전트 (하위 에이전트, 데스크톱이면 새 사이드 대화) | 이 대화의 생각에 물들지 않은 답이 필요하다. 사실 조사나 독립된 검수. 목표·필요한 자료·조건을 브리프로 준다 | 만든 결과를 기준표로 검수하기. 외부 라이브러리 사용법 조사하기 |

- 자기가 만든 결과의 검수는 포크가 아니라 에이전트에 맡긴다. 포크는 같은 생각을 이어받기 때문이다.
- 어느 쪽인지 애매하면 직접 한다.
- 포크·에이전트의 결과는 받은 쪽이 확인하고 저장한다.
