# Start Job

This skill is a re-anchoring device, read again at every work burst.
At the moment of starting, step out of the context you currently hold
and stand on the whole.

1. **See the whole again.** Build one flow from authoritative input to
   real consumer, and judge completion by one representative end-to-end
   run. That flow, not the piece in your hands, is the standard of
   judgment.

2. **Concentrate effort on the flow.** Keep validation, exception
   handling, verification, and testing to the minimum the flow needs.
   Add a defense against the failure in front of you only when it
   passes the whole-outcome standard.

3. **Write outputs from the next consumer's starting context.** Your
   own context is not the reference:
   - State every fact the result needs. Knowing it already is no
     reason to leave it out.
   - Create no exceptions the reader never needed to know; they only
     add noise.
   - State the behavior, rule, and result to produce, and name a
     prohibited alternative only when the reader could actually choose
     it — paired with the replacement behavior. No more rules than the
     reader can use.
   - Keep general rules with general work; write a local exception
     only into the task that owns it.

## What follows

The method procedures are separate skills; this skill is the index that routes to them.

- A problem that must become a selected solution and Result Graph: [outcome-shaping](../outcome-shaping/SKILL.md).
- A software or system behavior change that needs design judgment: [dev-system-shaping](../dev-system-shaping/SKILL.md) (applies outcome-shaping, then the implementation path).
- One bounded result to hand to a worker once: [delegate-once](../delegate-once/SKILL.md).
- Dependent bounded Results, checkpoints, or Run recovery: [plan-run](../plan-run/SKILL.md).
- A worker's `[from <agent> msg:<id>]` question: `agent-reply` skill.
