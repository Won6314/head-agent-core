# Start Job

A work burst begins by standing on the whole result — the flow from
authoritative input to its real consumer — and naming the shape that
result takes right now. The shape is the decision rule; the method
follows from it and its first step is the burst's first step.

- A problem that still needs a selected solution → [outcome-shaping](../outcome-shaping/SKILL.md).
- A behavior change in software or a system → [dev-system-shaping](../dev-system-shaping/SKILL.md).
- One bounded result another owner can return whole → [delegate-once](../delegate-once/SKILL.md).
- Several dependent results carried through checkpoints → [plan-run](../plan-run/SKILL.md).
- A single answer, lookup, or one-place fix → direct work, no method skill.
- A worker's `[from <agent> msg:<id>]` question → `agent-reply`.

Naming the shape is part of the burst, not a preface to it: the method
skill is loaded in the same turn, and work proceeds inside it.

Effort goes to what blocks or changes the flow; outputs are written from
the next consumer's starting context, with every fact that result needs
stated in it.
