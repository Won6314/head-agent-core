# Outcome Shaping

Use this general method before selecting execution ownership. It forms a
consumer-ready Result Graph; it does not start a delegation or rewrite a Run.

## Method

1. Define the current/needed-state problem and its real consumer.
2. Structure observable goals and the success evidence that consumer can use.
3. Compare material solution alternatives. Return product, policy,
   architecture, cost, workflow, or other user-owned choices before selecting
   a solution.
4. Record the selected solution and its locked decisions.
5. Form its Result Graph with independently consumable results, each result's
   consumer, authoritative inputs, observable output, acceptance boundary,
   dependencies, and mutation and preservation boundaries.
6. Select direct work when the result remains connected to HEAD's active
   context; select `delegate-once` for one independently executable result
   that can return once; select a durable Run when dependent results need
   checkpoints or recovery.

Read [problem-to-result.md](../../procedures/outcome-shaping/problem-to-result.md)
for the detailed method and examples.
