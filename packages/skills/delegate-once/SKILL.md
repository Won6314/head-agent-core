# Delegate Once

Use this workflow only after HEAD has directly established and retained the whole-outcome context and selected one independently executable result.

## Entry Contract

Before delegation, HEAD knows:

1. why the result is needed and its exact real consumer;
2. the required observable output or state and acceptance boundary;
3. the authoritative inputs and locked decisions;
4. the mutation and preservation boundaries;
5. the representative proof that will demonstrate the consumed result.

Local source inspection begins only inside this bounded result. Parent understanding, product or policy judgment, and integration decisions remain with HEAD.

## Slice And Dispatch

1. Select the worker that can own the bounded result end to end.
2. Load only the selected worker branch. For `developer`, read [developer.md](../../procedures/delegate-once/workers/developer.md).
3. Compile the smallest complete execution context from that worker's actual starting context. Spell out material facts and relationships unavailable there; an exact readable authority reference may carry source content, but HEAD's private context cannot.
4. State the required output, authoritative inputs, locked decisions, consumer, acceptance, mutation and preservation boundaries, and representative proof.
5. Express boundaries as the behavior and state to preserve. Name a prohibited alternative only when the worker could plausibly choose it and that choice would materially change the result; state the replacement behavior with it.
6. Dispatch only when the worker can implement, correct, verify, and return the result once without Run planning or checkpoints.

## Return And Reintegration

The worker returns artifacts, observed state, direct evidence, and any bounded contract conflict. HEAD inspects the returned result, reintegrates it into the whole-outcome context, and judges completion or the next path.
